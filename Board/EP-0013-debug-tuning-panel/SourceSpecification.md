# EP-0013 — Отладочная панель параметров боя и маневрирование корабля игрока

Статус: **planning-only / draft**, revision 2, 2026-10-22. 6 историй, 21 тикет. Внешние документы не нужны: ссылки ведут только на код репозитория.

> **Baseline.** Эпик опирается на ветку `codex/ep-0012-combat-rebuild` @ e134a2ca. Номера строк — подсказка. Перед US-0001 исполнитель заново сверяет пути и имена API и записывает расхождения в Code context тикета.

## 1. Цель

Во время игры на тактической карте менять параметры боя:
- скорость, ускорение и поворот Тетрарха и Мухи;
- скорость и радиус взрыва торпед и ПРО;
- перезарядку аппаратов.

Изменение сразу действует на все объекты, в том числе на торпеды и ПРО в полёте. После каждого изменения записывается файл со всеми значениями панели. При следующем запуске игра читает этот файл. Рядом лежит файл с дефолтными значениями. Баланс можно отлаживать правкой JSON и перезапуском, без компиляции.

Второе: игрок управляет кораблём с клавиатуры. A/D или ←/→ поворачивают, W/S или ↑/↓ разгоняют и тормозят. Пока клавиша зажата, действие идёт непрерывно. Поворот сочетается с разгоном или торможением (US-0006, §8).

## 2. Что входит и что нет

**Входит:**
- панель на тактической карте по клавише;
- команда движку, которая применяет изменения;
- немедленное применение ко всему, что есть в мире;
- файл текущих значений, файл дефолтов, чтение файла при старте;
- сохранение действующих значений в сейв;
- ручное маневрирование корабля игрока с клавиатуры (US-0006);
- RU/EN тексты и тесты.

**Не входит:**
- отладка других параметров: урон, броня, разброс, ИИ, дальность;
- маневрирование торпед. Торпеды и ПРО летят по прямой (решение D01 EP-0012), поворота у них нет;
- горячая перезагрузка файла во время игры. Файл читается только при старте сессии;
- правка каталогов `Data/**`. Панель их не меняет;
- скрытие панели в релизной сборке. По решению автора панель доступна всегда;
- управление мышью, геймпадом и задний ход: скорость не опускается ниже 0.

## 3. Решения

| ID | Решение | Источник |
|---|---|---|
| T01 | Параметры кораблей: максимальная скорость, ускорение, скорость поворота двигателя. «Маневренность» = ускорение + поворот | автор |
| T02 | Параметры торпед и ПРО: скорость и радиус взрыва каждого профиля, перезарядка аппарата | автор, вопрос 1 |
| T03 | Изменение применяется ко всему сразу, включая торпеды и ПРО в полёте | автор, вопрос 2 |
| T04 | Файл текущих значений читается при старте сессии. Файл дефолтов — только справка и источник сброса | автор, вопрос 3 |
| T05 | Панель доступна в любой сборке по клавише, без флага | автор, вопрос 4 |
| T06 | Параметр меняется у **типа модуля**, а не у одного корабля: все Мухи меняются вместе | эпик |
| T07 | Торпеды Тетрарха (`module.torpedo.launcher.basic`) и Мухи (`module.torpedo.launcher.light`) настраиваются отдельно. Профили у них одинаковые по составу, но значения независимы | эпик |
| T08 | Источник истины — движок. Клиент отправляет команду и показывает значения из снапшота. Файл пишет клиент после подтверждения движка | эпик |
| T09 | Изменение — обычная команда игрока. Она идёт в фазе команд игрока по порядку событий EP-0012 и поэтому детерминирована при повторе | эпик |
| T10 | Действующие значения пишутся в сейв. При загрузке сначала восстанавливаются значения из сейва, затем файл применяется как обычное изменение (§5.6) | эпик |
| T11 | Каталоги `Data/**` не меняются. Отладочные значения — слой поверх каталога | эпик |
| T12 | Клавиши маневрирования: поворот влево — A и ←, вправо — D и →; разгон — W и ↑; торможение — S и ↓. Прицел ПРО переезжает с W на **E**, уклонение с A/D на **Z/C**. Shift остаётся «полным ходом» | автор |
| T13 | Управление работает везде на тактической карте, в бою и вне боя. Старое поведение стрелок вне боя убирается: шаг поворота 1° и одиночные Accelerate/Brake | автор |
| T14 | Пока клавиша зажата, поворот идёт непрерывно со скоростью поворота двигателя, разгон и торможение — с ускорением двигателя. Отпустил поворот — курс держится. Отпустил W/S — корабль держит достигнутую скорость | автор |
| T15 | Поворот сочетается с разгоном или торможением одновременно. Противоположные клавиши одной оси (влево и вправо, разгон и торможение): действует последняя нажатая. При её отпускании, если первая ещё зажата, действие возвращается к первой | автор |
| T16 | Shift — полный ход одним нажатием: разгон до максимума продолжается и после отпускания Shift. Он прерывается нажатием W/S/↑/↓ или заканчивается на максимуме. Поворот его не прерывает | автор |
| T17 | Ручное маневрирование прерывает автоматическое движение: уклонение, орбиту, сближение, синхронизацию, циклы Accelerate/Brake/Turn*. Так же сейчас ведёт себя `engine.turnHold` | эпик |
| T18 | В движке скорость удерживается отдельным каналом `engine.speedHold`, параллельным `engine.turnHold`. Сейчас `turnHold` при старте отменяет все циклы двигателя, включая разгон (`SimulationEngine.TurnHold.cs:31-38`), и сочетание невозможно. Каналы друг друга не отменяют | эпик |
| T19 | Удержания не пишутся в сейв: после загрузки ввод отпущен, как при потере фокуса. Корабль летит с текущими курсом и скоростью | эпик |

## 4. Параметры панели и дефолты

Дефолты взяты из каталога на baseline. Единицы — как в каталоге, кроме скорости кораблей: там км/с вместо м/с.

### 4.1 Корабли (двигатели)

| Секция | Тип модуля | Параметр | Ключ файла | Дефолт | Шаг (Ctrl — мелкий) | Допустимо |
|---|---|---|---|---:|---|---|
| Тетрарх | `module.engine.tetrarch` | Макс. скорость, км/с | `maxSpeedKmS` | 5,0 | 0,5 (0,1) | 0,1–50 |
| | | Ускорение, м/с² | `accelerationMps2` | 600 | 50 (10) | 10–20000 |
| | | Поворот, °/с | `turnRateDegPerSec` | 20 | 2 (1) | 1–360 |
| Муха | `module.engine.strizh` | Макс. скорость, км/с | `maxSpeedKmS` | 8,0 | 0,5 (0,1) | 0,1–50 |
| | | Ускорение, м/с² | `accelerationMps2` | 1000 | 50 (10) | 10–20000 |
| | | Поворот, °/с | `turnRateDegPerSec` | 24 | 2 (1) | 1–360 |

Это поля `MaxSpeedMps`, `LinearInertiaMps2` и `AngularInertiaDegPerSec` в `ModuleTypeDefinition` (`src/DeepSpaceSaga.Engine/Content/ModuleTypeDefinition.cs`). Сейчас они `int`, поэтому ускорение и поворот целые. Скорость хранится в м/с: 5,0 км/с → 5000.

Поле `maneuverability` в каталоге двигателей — остаток старого боя с шансами. На физику point-боя оно не влияет, в панель не входит.

### 4.3 ПРО

| Секция | Тип модуля | Параметр | Дефолт | Шаг (Ctrl) | Допустимо |
|---|---|---|---:|---|---|
| ПРО Тетрарха | `module.countermeasure.launcher.basic` | Перезарядка, мс | 12500 | 500 (100) | 100–600000 |

| | профиль `fast` | то же | 25 / 0,5 | | |

Итого 29 параметров: 6 у кораблей, 2 × 7 у торпед, 5 у ПРО.

### 4.4 Важно знать при отладке (текст справки в панели)

- **Скорость Мухи на орбите.** Она не равна её максимальной скорости. `HostileOrbitMath.Plan` держит относительную скорость `min((макс − v_игрока) × 0,5; √(ускорение × 25 / 4); поворот_рад × 25 / 4)`. При дефолтах это 2,5 км/с относительно игрока. Поэтому рост максимальной скорости Мухи выше примерно 8 км/с почти не меняет орбиту: упор идёт в ускорение и поворот.
- **Если поднять скорость торпед выше скорости кораблей,** упреждение становится проще для обеих сторон.

## 5. Поведение движка

Новые значения вступают в силу в момент обработки команды t, в фазе команд игрока. Для каждого изменённого типа модуля:

### 5.1 Корабли с изменённым двигателем

1. Новая максимальная скорость сразу записывается в движение корабля (`MaxSpeedKmS`). Если текущая скорость выше нового максимума, она в момент t обрезается до максимума. Позиция не прыгает.
2. Активные сегменты движения перепланируются от позы в момент t с новыми лимитами:
   - ручной разгон и удержание поворота;
   - команды двигателя;
   - уклонение (`EvasionSteeringSnapshot`): пересчитываются лимиты и момент окончания возврата;
   - сегмент орбиты NPC (`HostileCombatSnapshot`).

   Конец уклонения (t* + 0,5) не меняется.
3. NPC берут новые значения из реестра на ближайшем решении (шаг 100 мс). Отдельно это делать не нужно.
4. Прогнозы и снапшоты публикуют новые значения: `InstalledModuleSnapshot.EngineMotion`, `MaxSpeedKmS` объекта.

### 5.2 Торпеды и ПРО в полёте

Для каждого живого снаряда изменённого аппарата и профиля:

1. Берутся позиция P(t) по старому полёту и точка подрыва A. A не меняется: прицел игрока или NPC сохраняется.
2. Полёт перестраивается: старт = P(t), время старта = t, скорость = новая, `t_det' = t + |A − P(t)| / v'`. Если |A − P(t)| = 0, подрыв происходит в момент t.
3. Новый радиус взрыва действует на ещё не взорвавшиеся снаряды.
4. Наблюдаемый снаряд (`ObservedProjectileSnapshot`) показывает новую скорость и радиус. Угрозы, тени и прогнозы пересчитываются сами из снапшота. Скрытые поля (A, t_det) по-прежнему не уходят к стороне, которая не владеет снарядом.
5. Счётчики боя, RNG разброса и идентификаторы снарядов не меняются. Разброс уже применён при пуске.
6. Если из-за нового `t_det'` несколько подрывов совпали по времени, они идут по порядку событий EP-0012: сначала ПРО, потом торпеды, порядок по ID.

### 5.3 Перезарядка

Для аппаратов этого типа в процессе перезарядки: `readyAt' = reloadStart + reloadMs'`, где `reloadStart = readyAt − reloadMs_старое`. Если `readyAt' ≤ t`, аппарат готов в момент t. Готовые аппараты не меняются. Следующая перезарядка идёт с новым значением.

### 5.4 Команда

- **Тип:** `debug.tuning.apply` в категории `debug`.
- **Payload:** `DebugTuningPatch`, список `(moduleTypeId, field, profileId?, value)`. Одна команда может нести несколько полей: панель шлёт одно, сброс — все.
- **Проверки:**
  - тип модуля из §4;
  - поле допустимо для этого типа;
  - профиль существует;
  - значение конечное и в диапазоне §4;
  - для `int`-полей значение целое.
- **Отказы:**

  | Код | Когда |
  |---|---|
  | `debug_unknown_parameter` | неизвестный тип модуля, поле или профиль |
  | `debug_value_out_of_range` | значение вне диапазона §4 или не целое для `int`-поля |
  | `debug_session_not_running` | сессия не запущена |

  При отказе не применяется ничего: патч атомарный.
- **Пауза.** Команда принимается и на паузе. Эффект §5.1–5.3 считается от текущего момента t.
- **Где работает.** Только на тактической карте. В доке и диалоге команда тоже принимается: это просто правка реестра.

### 5.5 Состояние и снапшот

- Движок хранит `DebugTuningState`: базовые значения из каталога, действующие значения и `Revision`. Ревизия растёт на каждой успешной команде.
- Реестр модулей (`GameDataRegistry.ModuleTypes`) получает новые определения через `with`. Индексы типов (`ModuleTypeIndex`) не меняются.
- Снапшот публикует `DebugTuningSnapshot { Revision, Values, Defaults }`. В компактных кадрах он идёт только при смене ревизии.
- Скрывать значения Мухи от игрока не нужно: это отладочный инструмент, решение O12 EP-0012.

### 5.6 Сейв и старт сессии

- **Сейв** пишет действующие значения в необязательное поле `debugTuning`. Если все значения дефолтные, поле отсутствует.
- **Загрузка сейва:**
  1. Реестр = каталог + `debugTuning` из сейва. На нём проходит валидация и восстановление: снаряды в полёте сверяются со своей скоростью.
  2. Затем, если файл §6.1 есть и валиден, его значения применяются как команда `debug.tuning.apply` в момент загрузки, с перестройкой по §5.1–5.3.
- **Новая игра или сценарий:** реестр = каталог + файл §6.1, если он есть и валиден.
- **Формат сейва.** Если загрузчик сейвов отвергает неизвестные поля, исполнитель поднимает формат до Save19 и пишет миграцию «Save18 = без отладочных значений». Если не отвергает — формат остаётся 18. Решение и причина записываются в тикет US3-TK1.

## 6. Файлы

Папка — `<папка игры>/DebugTuning/`, рядом с `Settings.json`, `Saves/` и `CombatMetrics/` (`AppContext.BaseDirectory`). Кодировка UTF-8, отступ 2 пробела, числа с точкой.

### 6.1 `debug-tuning.json` — текущие значения

- **Когда пишется.** После каждого успешного применения, когда снапшот принёс новую ревизию.
- **Что внутри.** Все 29 параметров §4 — полный набор, а не только изменённые.
- **Как пишется.** Атомарно: временный файл, затем замена. Не чаще раза в 250 мс; последняя версия записывается обязательно.
- **Что делает «Сбросить всё».** Применяет дефолты и удаляет файл. При следующем старте действует каталог.

```json
{
  "schemaVersion": 1,
  "writtenAtUtc": "2026-10-22T12:00:00Z",
  "ships": {
    "module.engine.tetrarch": { "maxSpeedKmS": 5.0, "accelerationMps2": 600, "turnRateDegPerSec": 20 },
    "module.engine.strizh":   { "maxSpeedKmS": 8.0, "accelerationMps2": 1000, "turnRateDegPerSec": 24 }
  },
  "launchers": {
    "module.torpedo.launcher.basic": {
      "reloadMs": 10000,
      "profiles": {
        "slow":   { "speedKmS": 6,  "blastRadiusKm": 9 },
        "medium": { "speedKmS": 10, "blastRadiusKm": 5 },
        "fast":   { "speedKmS": 16, "blastRadiusKm": 2.5 }
      }
    },
    "module.torpedo.launcher.light": {
      "reloadMs": 7250,
      "profiles": {
        "slow":   { "speedKmS": 6,  "blastRadiusKm": 9 },
        "medium": { "speedKmS": 10, "blastRadiusKm": 5 },
        "fast":   { "speedKmS": 16, "blastRadiusKm": 2.5 }
      }
    },
    "module.countermeasure.launcher.basic": {
      "reloadMs": 12500,
      "profiles": {
        "wide": { "speedKmS": 15, "blastRadiusKm": 1.0 },
        "fast": { "speedKmS": 25, "blastRadiusKm": 0.5 }
      }
    }
  }
}
```

**Чтение при старте:**
- **Частичный файл допустим:** отсутствующие ключи = значения каталога. Так файл можно править руками, оставив одну строку.
- **Строгость.** Неизвестный ключ, неверный тип, значение вне диапазона §4 или `schemaVersion ≠ 1` — **файл отвергается целиком**, действует каталог.
- **Что видит игрок при отказе.** В журнал клиента пишется предупреждение с путём и причиной. При первом открытии панели показывается красная строка «Файл отладки отвергнут: <причина>». Игра не падает.
- **Чтение только при старте сессии** (T04). Правка файла во время игры подхватится при следующей новой игре или загрузке.

### 6.2 `debug-tuning.defaults.json` — дефолты

- **Когда пишется.** Клиентом при каждом запуске игры, из каталога, без отладочного слоя. Формат как в §6.1, плюс поле `"source": "catalog"`.
- **Как используется.** Только справка: игра его не читает. Кнопка «Сбросить» берёт дефолты из `DebugTuningSnapshot.Defaults`, а не из файла.
- **Зачем.** Чтобы вернуть каталог руками, достаточно скопировать `debug-tuning.defaults.json` поверх `debug-tuning.json` или удалить `debug-tuning.json`.

## 7. Панель (UI)

- **Открытие.** Клавиша **F12** открывает и закрывает панель на тактической карте в любой момент и в любой сборке. Клавиша задаётся полем `debugPanel` в `Data/UI/combat-input.json`, по умолчанию `"F12"`. F12 не занята: сейчас используются F5, F9, F10. Esc закрывает панель, если открыта она, а не прицел.
- **Место и вид.**
  - Справа, поверх карты, ширина 360 px × масштаб UI, высота — до низа карты, прокрутка колесом.
  - Заголовок «Отладка боя», под ним строка статуса.
  - Секции сворачиваются: Тетрарх, Муха, Торпеды Тетрарха, Торпеды Мухи, ПРО Тетрарха. Порядок и состав — §4.
- **Строка параметра:**
  - название;
  - текущее значение;
  - кнопки «−» / «+» (шаг §4, с Ctrl — мелкий шаг);
  - кнопка «↺» — вернуть дефолт этого параметра.

  Если значение отличается от дефолта, оно выделено цветом `styles.Warning`, а рядом серым показан дефолт. Колесо над значением = «−» / «+».
- **Применение сразу.** Каждый клик шлёт `debug.tuning.apply` с одним полем. Пока ждём подтверждения, значение показано курсивом. После подтверждения строка статуса: «Применено · файл записан 12:00:05». При отказе — красная строка с локализованной причиной, значение возвращается к действующему.
- **Кнопки внизу:**
  - «Сбросить всё» — одна команда со всеми дефолтами и удаление `debug-tuning.json`, подтверждение вторым кликом за 1 с;
  - «Открыть папку» — открывает `DebugTuning/` в проводнике.
- **Справка.** Строка «?» раскрывает текст §4.4.
- **Ввод.**
  - Пока курсор над панелью, клики, колесо и наведение не уходят на карту: прицел, выбор угрозы и зум отключены.

- **Тексты.** Все строки — в `Locale/Russian.json` и `English.json` под ключами `Debug.*`. Имена параметров локализуются, ключи файла — нет.

## 8. Маневрирование корабля игрока (US-0006)

### 8.1 Клавиши

`Data/UI/combat-input.json` переходит на `schemaVersion: 2`:

```json
{
  "schemaVersion": 2,
  "torpedoAim": "Q",
  "countermissileAim": "E",
  "profiles": ["Number1", "Number2", "Number3"],
  "cancel": "Escape",
  "launchMouse": "Left",
  "cancelMouse": "Right",
  "wheelProfiles": true,
  "evadeLeft": "Z",
  "evadeRight": "C",
  "nextThreat": "Tab",
  "turnLeft": ["A", "Left"],
  "turnRight": ["D", "Right"],
  "accelerate": ["W", "Up"],
  "brake": ["S", "Down"],
  "fullSpeed": ["ShiftLeft", "ShiftRight"],
  "debugPanel": "F12"
}
```

- **Привязки.** `turnLeft`, `turnRight`, `accelerate`, `brake` — одна или две клавиши. Файл версии 1 читается с прежними значениями и дополняется дефолтами версии 2 для новых полей. Конфликт с прежними W и A/D разрешается в пользу версии 2, с предупреждением в журнале.
- **Клавиша S.** Сейчас S зарезервирована и без Ctrl до экрана не доходит:
  - `CombatInputSettings.Validate` запрещает её;
  - `KeyboardEdgeTracker.Down` пропускает её только с Ctrl;
  - `SkiaWindow` отправляет её как событие экрана.

  После изменения S без Ctrl — торможение, Ctrl+S — экран корабля, как раньше. I остаётся зарезервированной.
- **Свободные клавиши.** E, Z и C без модификаторов сейчас не используются: Ctrl+C остаётся за прежней функцией.
- **Подсказки клавиш в интерфейсе** (панели оружия, панель угроз, справка) берутся из привязок, а не из констант.

### 8.2 Поведение

Начальные значения для примеров — Тетрарх по каталогу: 5 км/с, 0,6 км/с², 20 °/с.

| Ввод | Результат |
|---|---|
| D зажата 3 с физики, курс 0° | курс 60°, скорость не меняется |
| W зажата 2 с, скорость 3 км/с | 4,2 км/с, курс не меняется |
| W зажата 5 с, скорость 3 км/с | 5,0 км/с через 3,33 с, дальше 5,0 |
| S зажата 6 с, скорость 3 км/с | 0 через 5 с, дальше 0, назад не едет |
| D + W зажаты 2 с, курс 0°, 3 км/с | курс 40°, 4,2 км/с, позиция — дуга с постоянными a = 0,6 и ω = 20 °/с |
| Зажата A, нажата D, отпущена D | поворот вправо, пока зажата D, затем снова влево |
| Зажата W, нажата S | торможение, пока зажата S; при отпускании S снова разгон |
| Короткое нажатие Shift при 3 км/с, затем D 2 с | поворот 40°, скорость растёт до 5 за 3,33 с без удержания Shift |
| Shift, затем S | полный ход прерван, торможение, пока зажата S |
| Клавиша отпущена | поворот: курс держится. Скорость: держится достигнутая |

- **Отправка команд.** Клиент шлёт команды только на смену состояния оси, не на повтор клавиши. Слева/справа и разгон/торможение — по стеку нажатий (T15). A и ← — синонимы: зажаты обе, отпущена одна — поворот продолжается.
- **Отключение и уничтожение.** Если двигатель отключён или уничтожен, удержания заканчиваются. Корабль летит с текущими курсом и скоростью. Когда двигатель снова доступен, а клавиша всё ещё зажата, клиент повторно шлёт удержание.
- **Где не работает.** В доке, в диалоге и после поражения команды не отправляются, отказ движка — `engine_disabled`.
- **Пауза.** На паузе нажатия принимаются, движение начинается с продолжением времени.
- **Потеря фокуса окна и загрузка сейва** отпускают весь ввод (поведение 821e0787 и T19).
- **Уклонение.** Z/C запускают уклонение, оно отменяет удержания. Чтобы маневрировать дальше, клавишу нужно нажать заново. Нажатие клавиши маневрирования во время уклонения прерывает уклонение (T17).
- **Прицел.** Маневрирование не закрывает прицел торпеды или ПРО. Клики мыши и клавиши маневрирования работают одновременно.

### 8.3 Движок

- **Команда `engine.speedHold`.** В `PlayerCommand` добавляются `SpeedDirection` (`Accelerate`/`Brake`), `Active` (как у `turnHold`) и `Latched` (только для Shift). Проверки как у `TryTurnHold`: свой корабль, модуль двигателя, двигатель доступен, не в доке.
- **Состояние движения.** У игрока в движении появляются `SpeedHoldAccelerationKmS2` (±ускорение двигателя или null) и `SpeedHoldLatched` рядом с существующим `TurnHoldRateDegPerSec`. Снапшот публикует их только в строке своего корабля, как `TurnHoldRateDegPerSec`.
- **Совместимость каналов.** `turnHold` больше не отменяет `speedHold`, и наоборот. Оба по-прежнему отменяют циклы двигателя, сближение и уклонение (T17).
- **Отпускание.** `speedHold` с `Active = false` по своему направлению снимает удержание. Отпускание противоположного направления игнорируется — так же, как у `turnHold` (`SimulationEngine.TurnHold.cs:20-25`).
- **Shift.** Шлёт `speedHold Accelerate Latched = true`. Его отпускание команду не шлёт. Удержание с защёлкой снимается на максимуме скорости или следующим `speedHold`.
- **Движение.** Постоянные a и ω — тот же аналитический сегмент, что `HostileOrbitMath.Sample` (`src/DeepSpaceSaga.Motion/HostileOrbitMath.cs`). В момент, когда скорость достигает 0 или максимума, сегмент делится: дальше a = 0, ω сохраняется. Делится и `CurrentManeuverForecast`, чтобы прогноз своего пути на 5 с совпадал с движком.
- **Стыки и детерминизм.** Проверки инвариантности к разбиению шага — как у уклонения и `turnHold`.
- **Отладочная панель.** Смена ускорения или поворота через панель (US-0002) перестраивает активные удержания с новыми лимитами (§5.1).

## 9. Правила исполнения

- Один тикет — один слой и не больше 5 файлов. Порядок — §10.
- Сборка: `dotnet build DeepSpaceSaga.sln` без предупреждений. Тесты затронутых проектов зелёные. Тесты баланса (`Trait=Balance`) не обязательны.
- Self-review не заменяет независимое ревью.
- После каждого коммита агент сразу выполняет push. Перед push проверяет целевую ветку и remote, после push подтверждает совпадение SHA удалённой ветки с локальным HEAD. Локальный коммит без подтверждённого push не считается публикацией.

### US-0002 — Немедленное применение

**User story.** Как разработчик, я меняю скорость и сразу вижу, как изменилось движение кораблей и снарядов, включая уже летящие.

- **US2-AC1:** Максимум Тетрарха снижен с 5 до 2 км/с, корабль летел 4,5 км/с → в момент команды скорость 2,0, позиция непрерывна (разрыв ≤ 1e-6 км). Через 1 с физики расстояние = 2 км ± 1e-6.
- **US2-AC2:** Поворот Мухи увеличен с 24 до 48 °/с → на ближайшем решении (≤ 100 мс) `HostileCombatSnapshot.Segment.TurnRateDegPerSec` ограничен 48. Уклонение игрока во время изменения перепланировано: `ReturnsAtMotionTimeMs` соответствует новым лимитам, конец уклонения тот же.
- **US2-AC3:** Торпеда `medium` летит из (0, 0) в (40, 0) км на 10 км/с, на t = 2 с скорость меняется на 20 км/с → позиция в t = 2 с равна (20, 0), `t_det` = 2 + 20/20 = 3 с, взрыв в (40, 0).
- **US2-AC4:** Радиус `slow` торпед Мухи 9 → 12 км до подрыва летящей торпеды. Корабль в 10 км от точки подрыва получает урон с `k = falloff(10, 12, 0,3)` = 0,2381. Без изменения урона бы не было.
- **US2-AC5:** Перезарядка basic 10000 → 5000 мс, аппарат выстрелил 3 с назад → готов через 2 с. Если выстрелил 6 с назад → готов в момент команды.
- **US2-AC6:** Два прогона с одним сидом и одной последовательностью команд, включая `debug.tuning.apply`, дают одинаковые снапшоты: проверка инвариантности к разбиению шага.

### US-0006 — Маневрирование корабля игрока

**User story.** Как игрок, я веду корабль с клавиатуры. A/D или ←/→ поворачивают, W/S или ↑/↓ разгоняют и тормозят. Пока клавиша зажата, действие идёт непрерывно. Поворот можно сочетать с разгоном или торможением.

- **US6-AC1:** Все строки таблицы §8.2 воспроизводятся тестами движка с погрешностью 1e-6 по курсу, скорости и позиции.
- **US6-AC2:** D + W: позиция через 2 с совпадает с `HostileOrbitMath.Sample` для сегмента (3 км/с, курс 0°, a = 0,6, ω = 20 °/с) до 1e-6 км. Разгон, поворот и торможение до упора делят сегмент в момент достижения предела.
- **US6-AC3:** `turnHold` во время `speedHold` не отменяет разгон, и наоборот. Оба отменяют циклы `engine.accelerate/brake/turn*`, `engine.orbit`, сближение и уклонение с результатом `Cancelled`.
- **US6-AC4:** Клиент шлёт ровно одну команду на смену состояния оси. Удержание клавиши 10 с — одна команда старта и одна стопа. A и ← зажаты вместе, отпущена одна — команды стопа нет.
- **US6-AC5:** Стек противоположных клавиш (T15) для поворота и для скорости — по таблице §8.2.
- **US6-AC6:** Shift: защёлка держится до максимума скорости. W/S/↑/↓ её снимают. Поворот её не снимает.
- **US6-AC7:** Управление работает вне боя (сценарий `PlayerShipOnly`) так же, как в бою. Стрелки вне боя больше не шлют `engine.turnLeftStep/turnRightStep` и одиночные `engine.accelerate/brake`.
- **US6-AC8:** S без Ctrl — торможение, Ctrl+S — экран корабля. E — прицел ПРО, Z/C — уклонение влево/вправо. Подсказки в интерфейсе показывают E, Z, C.
- **US6-AC9:** `combat-input.json` версии 1 читается: новые поля берутся из дефолтов версии 2, конфликт W/A/D разрешается в пользу маневрирования с предупреждением.
- **US6-AC10:** Отключение двигателя снимает удержания. После восстановления при зажатой клавише удержание шлётся снова. Потеря фокуса и загрузка сейва отпускают весь ввод.
- **US6-AC11:** Прогноз своего пути на 5 с (UI-02 EP-0012) при D + W совпадает с позицией движка через 5 с до 0,01 км.
