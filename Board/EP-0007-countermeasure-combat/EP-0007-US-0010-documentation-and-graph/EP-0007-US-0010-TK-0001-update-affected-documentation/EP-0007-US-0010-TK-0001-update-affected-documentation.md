Завершить эпик синхронизацией всех затронутых документов с поставленной реализацией. Пользователь прямо запросил такой финальный тикет; это не ограничивается созданием одного нового руководства.

## Dependencies

Шаг34, после [US9/TK3](../../EP-0007-US-0009-countermeasure-acceptance/EP-0007-US-0009-TK-0003-native-defense-acceptance/EP-0007-US-0009-TK-0003-native-defense-acceptance.md) и всех его транзитивных зависимостей. Сверить реальные результаты, а не только статусы Board.

Production API не меняется. Разрешены только затронутые EP-0007 текстовые документы в Documentation/, документационные README в репозитории, а также сводные документы EP-0006/EP-0007 в Board/. Предварительные точки проверки:

Это исходный перечень для инвентаризации, не утверждение, что каждый документ нуждается в правке. До редактирования записать точные пути/разделы и причины в таблицу impact audit внутри CountermeasureCombat.md. Внести туда и остальные найденные связанные документы. Объём — все затронутые тексты, без лимита5; прочие правила scope production-тикетов неизменны. AGENTS/skill-файлы, игровой код, тесты и runtime data не изменять.

## Implementation steps

1. Прочитать Documentation/00-Process/DocumentationSystem.md. Сопоставить итоговый diff эпика, его решения и реализованные API с документацией. Искать через rg по именам типов/команд/схем и терминам боя; пройти входящие ссылки.
2. Составить impact audit: путь, раздел, причина, действие (обновлён/не затронут), проверка. Не считать пустой поиск доказательством полноты.
3. Обновить существующие канонические описания; не создавать конкурирующий источник истины. Описать операторов/навыки, точную формулу и округление, момент броска, радиус/скорость/поворот, одноразовую попытку, все фазы и таймеры, target-loss, самоуничтожение, UI, журнал, палитру, версиюSave и legacy policy.
4. Отделить первоначальный план от фактической реализации. Указать отклонения с основанием; не маскировать невыполненный native smoke или известную проблему.
5. Обновить ссылки/индексы, примеры и инструкции воспроизведения. Зафиксировать дату и исходное состояние репозитория для последующей перестройки графа.

## Assumptions / Out of scope

Точный перечень определяется по итоговому коду, поэтому files_touched уточняется инвентаризацией, а не произвольным числом сейчас. Обновление документации не разрешает менять реализацию ради соответствия старому плану. Вновь обнаруженные дефекты оформляются отдельно.
