# EP-0007 — Противоракетная защита

Игрок атакует существующего пирата торпедами; пират автоматически пытается их перехватить. Игрок заранее видит шанс, при встрече происходит один бросок, а журнал объясняет результат. Операторы, самоуничтожение, интерфейс и продолжение боя после Save/Load входят в эту поставку.

## Источник и статус

Запрос: «Хорошо. Давай сделаем эпик по противоракетам. Задавай вопросы по одному так чтобы я мог отвечать цифрами вариантов - я с телефона. Помни что противоракета должна ориентироваться на механики баттлброзерс».

Источник решений — интервью в этой беседе; номера вариантов без контекста не являются самостоятельными требованиями. Ниже записана семантика ответов, без выдуманных дословных цитат и timestamps каждого ответа. Дата оформления 2026-10-04. Позднее исправление D10 имеет приоритет. Последний ответ «1» закрепляет D14.

Это **план**, не выполненная реализация. Все истории/тикеты draft; complete относится к нарезке плана. Основание структуры — Board/EP-0006 и DSS-EpicBuilder/DSS-StoryBuilder из D:/DeepSpaceSaga/Agents. Требуемый репозиторием requirements-engineer не найден; использован доступный Board workflow. Исходные требования не изменены. [EngineRequirements](../../Documentation/01-Requirements/EngineRequirements.md) и [CLAUDE](../../Documentation/00-Process/CLAUDE.md) сохраняют архитектурные инварианты.

## Границы и формальные правила

- Engine владеет шансом, RNG, событиями, состояниями/таймерами и уроном. Contracts передаёт immutable данные; shared Motion вычисляет движение; Client только проецирует и отправляет команды через session.
- Стартовая p=50.0% при обоих рейтингах30. Если рейтинг торпеды48, защиты30, p=32.0%. Это не отношение рейтингов.
- Мир:1unit=100м. Радиус100км=1000units, контакт500м=5units. Дистанции не зависят от zoom. Pixel5/50 — исключительно изображение.
- Предсказание должно найти встречу до первого прогнозируемого hull contact торпеды с учётом допуска, а не после достижения центра.
- Попытка помечается атомарно при успешном созданииPR; rejected/busy/nooperator/zerochance/unreachable не меняют RNG и marker.
- Generic torpedo collision также исключаетPR. Иначе обычный контакт обошёл бы бросок или уничтожил торпеду после промаха.
- Жизненный цикл: Ready → Guiding → Reloading → Ready. Miss: Guiding → MissedCoast → Reloading. Потеря цели: Guiding → Reloading сразу. Missing operator — отдельное состояние; autoEnabled отдельный флаг.
- Торпедный аппарат освобождается при завершении его торпеды, без нового cooldown. PR аппарат занят до конца полёта и последующего reload.
- Назначения сценарные; нельзя управлять аппаратом NPC через player commands. Автономная защита использует общий validated execution, а не обход ownership.
- Повтор selfDestruct привязан к ID прежней торпеды: не может уничтожить следующую. Команды и события идемпотентны.
- Рейтинг торпеды фиксируется при её пуске; rating breakdown и p PR — при пускеPR. Изменение текущего состояния экипажа/выбора не переписывает прошлое.
- Только три фактических попадания по450HP с damage150 уничтожают Тетрарх. Успешно перехваченная торпеда не наносит урон. Пират сохраняет прямолинейное движение; после гибели неподвижный новый Wreck. Остальные инвариантыEP6 сохранены.

| Таймер | Домен | Пауза | Ускорение |
|---|---|---|---|
| Полёт, coast2с, reload10с | Физическое время симуляции | Стоит | Следует скорости симуляции |
| Кольцо, текст результата, self-destruct terminal trail2с | Монотонное реальное время Client | Продолжается | Не ускоряется |
| История журнала | Сохраняемые факты с physical timestamp | Сохраняется | Не задаёт анимацию |

## Технические assumptions (решения автора плана, не цитаты пользователя)

A01. Новое помещениеPR — симметричная клетка (5,2); существующие модули не сдвигать. Две существующие каюты достаточны для двух операторов. Сохранить личность имеющегося персонажа игрока.

A02. Округлять только итог: ChanceTenths=Round(clamp(50+Rpr−Rt,0,100)*10,AwayFromZero). Roll равномерный integer1..1000, успех при roll<=ChanceTenths. На контакте100% тоже один draw; при0% нет пуска/броска. До вычитания рейтинги не округляются.

A03. Named stream combat.countermeasure.intercept.v1 выводится через существующий RngStreamSeedDerivation. Алгоритм, version/state/counter фиксируются, тестируются golden vectors реального production helper. Не использовать System.Random как подмену доказательства. Выбор конкретного стабильного алгоритма документируется в math/RNG тикете.

A04. При одинаковом времени порядок событий стабилен: hull contact торпеды имеет приоритет над interception, то есть равновременный перехват не спасает корабль; затем target loss безRNG. Несколько interception упорядочены по времени,PR ID,target ID (ordinal). Выбор incoming torpedo: ближайшее прогнозируемое попадание, затемID. Границы обрабатываются внутри длинного шага, не только на концах.

A05. SaveFormat v10 → v11, точная версия проверяется перед реализацией. Старые сохранения не получают выдуманных операторов; новые пуски без назначения запрещены. Уже летящая legacy торпеда без rating получает migration rating30 с явным признаком происхождения. НетPR встаромsave — нет скрытой добавленной защиты.

A06. После уже совершённого промаха последующее исчезновение цели не сокращает двухсекундный coast; случай D10 применяется только к неразрешённому Guiding. Исчезновение/гибель владельца отменяет егоPR без нового урона/RNG; дальнейший reload отсутствующего модуля не нужен.

A07. Journal MVP не обрезается скрыто; возможный лимит/архивирование — будущая задача. Text localization строится над numeric событиями; эффекты и их текущая фаза не сохраняются. При restore устанавливается watermark существующих событий, новые эффекты после него отображаются.

A08. Proposed API names допускают уточнение внутри того же контракта и allowlist. Новые файлы планируются явно; изменившийся baseline требует актуализации тикета до реализации. Все тестовые имена ниже планируемые, а не доказательства прохождения.

4. Native: реальные окно/input, zoom/scale,2real seconds наpause/speed, restartpalette, обе панели/journal. Не заменяется headless tests.
