# US-0020 — Баги

[Эпик](../EP-0012-combat-rebuild.md) · [Контракт](../Documentation.md) · [Порядок](../Tickets.md)

## Входное техническое задание

Прямой запрос пользователя 2026-10-21: новая история «Баги» и исходные четыре тикета; дополнение: «Сделай два тикета там же и добавь требования в документацию». Итого шесть тикетов по прямому указанию пользователя. Скриншоты — свидетельства симптомов, не инструкции на исполнение.

## User story

Как игрок, я вижу полный прогноз выбранного манёвра, прежнюю информацию о своём корабле и сведения о модулях в левых панелях. NPC-торпеда показывает своё положение и пройденный путь, а выбор точки пуска завершается после отправки команды.

## Acceptance criteria / Решения пользователя

**D20-01 / US20-AC1:** После Ctrl+ЛКМ прогноз выбранного манёвра достигает указанной точки и непрерывно продолжается по прямой до выхода за экран. Дальний выбор не обрезается горизонтом 5 секунд. Геометрия поворота соответствует текущей модели движения; нельзя заменить манёвр выдуманной прямой от корабля к точке.

**D20-02 / US20-AC2:** Справа Player Ship возвращается к прежней корабельной карточке: изображение и доступные корабельные сведения ObjectInfoPanelData/BuildLines (имя, скорость, направление и остальные ранее применимые поля). Вся информация о модулях, включая броню/структуру, состояние, предупреждения и сводки, переносится в соответствующие левые модульные панели. Ничего из прежних модульных сведений не теряется. Selected Object и Combat reports сохраняют работу.

**D20-03 / US20-AC3:** NPC-торпеда отображается только точкой с небольшим активным хвостом позади, длина которого зависит от скорости, и едва заметной почти чёрной линией уже пройденного пути. Не показываются стрелка направления, будущий луч, прогноз пути или точка назначения. История строится только из display-admitted позиций; скрытые или будущие кадры не используются. Стиль собственной торпеды и логика угроз сохраняются.

**D20-04 / US20-AC4:** При активном торпедном прицеливании один ЛКМ по допустимой точке без дополнительного предупреждения фиксирует координаты и инициирует ровно одну команду. После успешной постановки отправки PointAim и preview очищаются сразу. Перенос мыши не выбирает новую точку, следующий обычный ЛКМ не запускает вторую торпеду. Ожидание/ошибка команды остаются видны в панели оружия. Новый пуск требует явного входа в прицеливание. Действующие проверки дальности, готовности и friendly-fire сохраняются: до обязательного подтверждения или при невозможности начать отправку выбор остаётся активным.

**D20-05 / US20-AC5:** По завершении каждого цикла перезарядки торпедного аппарата игрока Engine формирует подтверждённое событие с идентификатором аппарата и физическим временем завершения. Игрок один раз слышит звуковой сигнал и получает сообщение «Торпедный аппарат <имя> перезаряжен» в боевом журнале и Combat reports. Событие не повторяется при новых кадрах, повторах доставки, паузе или загрузке уже завершённого цикла. Незавершённый сохранённый цикл уведомляет один раз после завершения. Готовность аппарата при старте новой игры сама по себе не является завершением перезарядки. Уведомления не раскрывают перезарядку NPC.

**D20-06 / US20-AC6:** В активном бою доступны пауза и скорости 1×, 2×, 5×, 10×. Это реальные множители базового темпа: за 4 реальные секунды продвигается соответственно 1/2/5/10 физических секунд. Engine принимает эти значения, UI показывает выбранное подтверждённое значение; 20× и 100× в бою недоступны. Пауза не продвигает бой, AI и перезарядку. Переключение не меняет физические длительности/правила боя и порядок событий; countdown/ETA пересчитываются по текущему множителю. Загрузка боя с любой разрешённой скоростью корректна. После боя сохраняется прежнее правило восстановления добоевой скорости.

## Dependencies / Non-goals

Используется текущая реализованная база EP-0012. Новых prerequisite tickets нет. Рекомендуемый порядок TK-0001 → TK-0002 → TK-0003 → TK-0004 → TK-0005 → TK-0006: общие файлы править последовательно, межтикетных API dependencies нет. TK-0001–0004 остаются Client-only. TK-0005–0006 — два сквозных feature tickets с конечными allowlists Contracts/Engine/Client и matching tests: техническое исключение для сохранения ровно двух запрошенных карточек. Production-код, игра и commit/push не выполняются в planning. Балансные значения не меняются; runtime/save consumers входят в scope будущих новых тикетов.

## Assumptions / Gaps

- A20-01: «старая информация» — изображение корабля и применимые поля ObjectInfoPanelData/BuildLines. Не добавлять выдуманные поля. Все прежние модульные сведения, включая предупреждения и сводки, остаются доступны слева.
- A20-02: «за экран» — прямой сегмент выходит за viewport и клипуется; бесконечное физическое моделирование не требуется.
- A20-03: предлагаемый хвост монотонно зависит от скорости при одном масштабе, имеет короткий экранный предел, при нулевой скорости длина ноль. Пройденный след почти чёрный. Точные пиксели/цвет выбрать и проверить при реализации; это не числовое решение пользователя. Короткий хвост позади разрешён, отдельный вектор/будущая линия запрещены.
- A20-04: выход из aiming — при успешной постановке отправки без ожидания projectile. Friendly-fire confirmation сохраняется; pending/error видны в оружии. Автоматического возврата в aiming после ошибки нет.
- G20-01: описание и screenshots не доказывают первопричину/исправление; automated/native/product acceptance новой реализации OPEN.
- G20-02: graphify-out отсутствует в текущем checkout; grounding по исходникам baseline 89e084c6.
- US20-AC1 заменяет конфликтующее own path 5s только для выбранного манёвра; AC2 переносит модульные сведения справа влево; AC3 убирает будущую линию NPC-торпеды; AC4 завершает торпедное aiming после отправки. Остальные AC эпика сохраняются.
