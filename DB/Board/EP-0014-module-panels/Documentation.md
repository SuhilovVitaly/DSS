## Решения из запроса, assumptions и gaps

D-01. M01–M09 — требования автора входного ТЗ; это не human approval созданных
историй. Реальные секунды = motion seconds / MotionTimeMultiplier текущей скорости.
На паузе для отображения применяется последняя ненулевая скорость, начально 1×.

D-02. Исходные номера US сохранены. Новые сведения snapshot входят в результат
пользовательских US-0001/0004; US-0005 отвечает за завершённую совместимость и
очистку после них. Это устраняет цикл «панели ждут US5, US5 ждёт панели».
Конкретные места полей и разбиение по слоям определяются в режиме тикетов.

D-03. Локализация — сквозное требование каждой панели; US-0006 принимает полное
покрытие RU/EN и актуальное руководство. Без неё отдельная история не разрешает
вводить постоянные нелокализованные подписи.

A-01. Сохраняем шесть исходных историй. Шесть предложенных тикетов US1 при
последующей детализации нужно объединить/пересрезать до максимум пяти, сохраняя
ценность и границы файлов. Это не утверждённый перечень тикетов.

A-02. Числовые примеры относятся к зафиксированной тестовой конфигурации без
debug overrides. При изменении snapshot/config показываются принятые значения.

G-01. Устаревший baseline0e67e2b8 заменён проверенным baseline выше. Save18-only
проверка недостаточна: требуется текущий Save19 и миграция 18, сохранение RNG,
deadlines, overrides и continuation. Наличие EP12/EP13 кода не закрывает их human gates.

G-02. M05 явно разрешает вход при reload/disabled; AC дополнительно требует «то же»
для destroyed/no operator. Для US1-review требуется уточнить допустимость входа
именно у уничтоженного модуля. Пока обязательны видимая причина и запрет запуска;
разрешение aim у destroyed остаётся открытым, без выдуманного согласования.

G-03. Макет двигателя смешивает скорость 3.2 с временем 13 с. По формуле: (5−3.2)/.6/.25
=12 с; при 3.0 получается 13.33 с. В completion evidence используются две явные фикстуры.
Ускорение/поворот 0 не должны давать NaN/infinity или ложное время.

G-04. M07 говорит «ядро приходит из snapshot», а M04 задаёт R×CoreFraction.
Assumption для review: допустима display-проекция двух авторитетных величин;
дублировать combat damage/falloff на Client нельзя.

G-05. Тип int? для penetration во входном ТЗ расходится с decimal? источника.
Нельзя терять дробную точность; выбор wire-типа и consumers проверяется до тикетов.

G-06. AC про нулевые allocations нужно измерять на пути панели после прогрева,
с фиксированными входами, культурой/viewport/hover и исключёнными внешними
анимациями. Проверка только форматтера недостаточна; zero-allocation всего
GameSessionScreen.Render исходными фактами не подтверждена. Границу измерения
согласовать на review US4, не объявлять готовой.

G-07. Для ПРО «не успевает» опирается на допущенный прогноз/точку перехвата;
скрытые будущие состояния NPC недоступны. Проверить соответствие live aim preview.
При неизвестном прогнозе не показывать фиктивное время или уверенное «Недостижимо».

G-08. Доступного graphify-out/graph.json в репозитории и workspace нет.
Grounding выполнен прямой проверкой исходников; граф не строился.

## 1. Цель

Панели модулей на тактической карте должны давать игроку всё нужное для боя по точке и не врать:
- **торпедный аппарат и ПРО:** номера профилей и выбранный профиль, радиус ядра, урон и бронепробитие, дальность, перезарядка с таймером, время полёта и разброс в км до курсора, понятная причина, почему нельзя стрелять;
- **двигатель:** лимиты (скорость, ускорение, поворот) и текущая скорость;
- **общее:** правильный приоритет раскрытия панелей, понятные строки состояния модулей, единые единицы времени, локализация всех значков, очистка устаревших полей контрактов.

- **Управление.** Клик по заголовку сворачивает группу и делает её предпочтительной (CP:481-496). Колесо прокручивает на 48 px (CP:739). При наведении на кнопку её подпись заменяет строку статуса (CP:659-664).
- **Строки модулей появляются только в бою** (`Snapshot.Encounter != null`, `GameSessionScreen.cs:1428-1434`). Для каждого модуля группы (CP:19-42):

- **Модули без своей группы** (генератор, контейнер, жилой модуль, мостик) идут в «Навигацию». Там же первая строка «Уничтожено модулей: n/3».

## 3. Решения

| ID | Решение |
|---|---|
| M01 | **Время.** Все значения времени в панелях — реальные секунды при текущей скорости игры: таймеры, перезарядка, время полёта, отключение. На паузе используется скорость, с которой игра была на паузу поставлена (по умолчанию x1). Подсказка у любого значения времени: «реальные секунды при x<k>; физических: <n> с» |
| M02 | **Номера профилей.** У строки профиля номер клавиши из привязок (`profiles` в `combat-input.json`) и пометка выбранного профиля. Вне прицела пометка показывает профиль, который будет выбран при входе в прицел |
| M03 | **Запоминание профиля.** Выбранный профиль запоминается отдельно для каждого аппарата на время сессии. При первом входе в прицел берётся `defaultTorpedoProfile` / `defaultCountermissileProfile` из `Data/UI/combat-visuals.json`. Дефолт — `medium` для торпед и `wide` для ПРО. Если такого профиля нет, берётся первый |
| M04 | **Ядро.** Показывается радиус ядра `R × CoreFraction` — зона полного урона. У ПРО ядра нет: она уничтожает снаряды во всём радиусе, поэтому показывается только R |
| M05 | **Прицел и причина блокировки.** Войти в прицел можно на перезарядке и при отключённом аппарате, чтобы подготовить выстрел. Кнопка показывает причину: «Перезарядка 12 с», «Нет оператора», «Отключён 6 с», «Уничтожен». Клик по карте, когда стрелять нельзя, не молчит: строка статуса и метка у курсора красным показывают причину |
| M06 | **Время полёта и σ до курсора.** В прицеле у каждого профиля время полёта до точки под курсором = дистанция / скорость профиля, и σ в км = `EffectiveScatterPercent × дистанция`. Это та же формула, что у «тени» прицела (`GameSessionScreen.TorpedoAimPreview.cs`). Вне прицела показывается σ на типовой дистанции 25 км |
| M07 | **Чего клиент не считает.** Урон, бронепробитие, предел уничтоженных модулей и ядро приходят из снапшота. Правила боя клиент не дублирует |
| M08 | **Двигатель.** Панель показывает лимиты из `EngineMotion` и текущую скорость. Изменения из отладочной панели EP-0013 видны сразу, потому что берутся из снапшота |
| M09 | **Очистка контрактов** идёт отдельной историей, последней по коду, после перевода клиента на новые поля |

## 4. Торпедный аппарат (US-0001)

### 4.1 Макет

```
(◔ 31 с) Торпедный аппарат                    [☑ 70 км]
 [ Прицел  Q ]  [ Подрыв ]
 Иванов · точность 20 · σ 0.42 км на 25 км
 1   медленный   6 км/с   R 9   ядро 2.7
 2 ▸ средний    10 км/с   R 5   ядро 1.5
 3   быстрый    16 км/с   R 2.5 ядро 0.75
 Урон 200 · бронепробитие 20 % · перезарядка 40 с
 Готов
```

В прицеле, курсор на 25 км:

```
 1   медленный   6 км/с   R 9   ядро 2.7    16.7 с · σ 0.42
 2 ▸ средний    10 км/с   R 5   ядро 1.5    10.0 с · σ 0.42
 3   быстрый    16 км/с   R 2.5 ядро 0.75    6.3 с · σ 0.42
```

### 4.2 Правила

- **Кольцо перезарядки** в заголовке: дуга плюс число оставшихся секунд, целое (`31 с`), а при значении меньше 10 — с десятыми (`4.2 с`). На готовом аппарате число скрыто.
- **Чекбокс кольца дальности** подписан дальностью: `70 км`.
- **Кнопка «Прицел»:** клавиша из привязок без скобок. Состояние по M05: обычная, если стрелять можно; приглушённая с причиной, если нельзя.
- **Строка оператора:** «Имя · точность N · σ X км на 25 км», где X = `EffectiveScatterPercent × 25`. Без оператора: «Нет оператора — пуск невозможен» красным.
- **Строки профилей:** номер клавиши, пометка «▸» (M02), название, скорость, R, ядро. Числа выровнены по колонкам. В прицеле добавляются время полёта и σ по M06; если курсор дальше дальности, вместо них «вне дальности».
- **Строка характеристик:** «Урон D · бронепробитие P % · перезарядка T с». T — полная перезарядка в реальных секундах (M01).
- **Строка статуса:** как сейчас, но таймер перезарядки остаётся видимым и при наведении на кнопку. Подпись кнопки при наведении выводится отдельной строкой подсказки над статусом.

 Петров · точность 20 · σ 0.67 км на 10 км
 1 ▸ широкий  15 км/с  R 1.0

- Правила те же, что в §4.2. Отличия:

## 6. Двигатель (US-0003)

```
 Двигатель Тетрарха
 [Разгон] [Торможение] [Держать скорость]
 Скорость 3.2 / 5.0 км/с  ▕██████░░░░▏
 Ускорение 0.6 км/с² · поворот 20 °/с
 Разгон до максимума: 13 с · разворот на 90°: 18 с
```

- Значения берутся из `InstalledModuleSnapshot.EngineMotion`, текущая скорость — из позы своего корабля.
- Последняя строка — справка для ручного управления. Время в реальных секундах при текущей скорости игры (M01):
  - разгон до максимума: (макс − текущая) / ускорение;
  - разворот на 90°: 90 / поворот.
- Если двигатель отключён или уничтожен, строки лимитов приглушены, статус «Отключён N с» / «Уничтожен».

## 7. Общая панель (US-0004)

- **Приоритет раскрытия (P1).** Порядок раскрытия при нехватке высоты задаётся по виду панели, а не по имени: предпочтительная → торпедные аппараты → ПРО → «Навигация» → «Двигатель» → «Контроль пространства» → остальные. Вид панели (`WeaponPanelInstance` или имя группы) определяется явно. Строковые имена `"Torpedo Launcher"` в CP:607 убираются.
- **Строки модулей в бою:**

  ```
  Торпедный аппарат !     Броня ▕██████▏ 60   Структура ▕█████░▏ 120
  ```

  - **Броня и структура:** полосы с числами и подписи «Броня» / «Структура» (P9). Полная форма «60/60» видна в подсказке.
  - **Состояние модуля:** «Отключён N с» / «Уничтожен». У аппаратов строка «Готов» в строке модуля не выводится (P10): её показывает строка статуса аппарата.
  - **Попадание:** «−140» на 0,8 с, без изменений.
  - **Критичность:** « !» заменяется значком и подсказкой «Критичный модуль: потеря уничтожает корабль».
- **«Уничтожено модулей: n / L» (P8).** L берётся из снапшота (§8). При n = L − 1 строка красная.
- **Время (P7).** Таймеры и длительности — по M01, с подсказкой.
- **Локализация (P9).** Все значки и сокращения выносятся в `Locale/*.json` под ключами `Combat.Panel.*`: R, ядро, σ, «▸», «вне дальности», «Броня», «Структура», «Критичный модуль», единицы. Имя клавиши берётся из привязок.
- **Мёртвый код (P11)** удаляется: `ObjectInfoPanel.OwnModuleDiagram`, `CommandsPanel.HoveredWeaponPanel` (если остаётся неиспользуемым), `ActivePanels`.
- **Производительность.** Строки пересобираются только при смене данных: ревизии снапшота, курсора в прицеле, скорости игры. В кадре без изменений нет выделений памяти и LINQ. SKPaint и SKFont создаются один раз.

### US-0005 — Контракты и движок

**User story.** Как разработчик, я получаю в снапшоте всё, что показывает панель, а устаревших полей боя с шансами в контрактах больше нет.

- **US5-AC1:** `LauncherCombatSnapshot.ArmorPiercingPercent` = 20 у обоих торпедных аппаратов. `DestroyedModuleLimit` = 3 у Тетрарха, только в строке своего корабля.
- **US5-AC2:** Поля §8 удалены из снапшотов. Сериализованный снапшот их не содержит. Сейвы Save18 загружаются.
- **US5-AC3:** Grep по `src/` не находит обращений к удалённым полям вне DTO сейва.

Тикеты:
- **TK-0001 — `snapshot-additions` · Contracts + Engine.** Новые поля и их заполнение. Тест US5-AC1.
- **TK-0002 — `legacy-launcher-fields` · Contracts + Engine.** Удаление из `LauncherCombatSnapshot` и `InstalledModuleSnapshot`. Тесты US5-AC2, AC3.
- **TK-0003 — `legacy-defense-fields` · Contracts + Engine.** Удаление из `DefenseSnapshot`. Тесты US5-AC2, AC3.

### US-0006 — Тексты и документация

**User story.** Как игрок, я вижу все подписи панели на своём языке. Как разработчик, я нахожу описание панели в документации.

- **US6-AC1:** Все строки §4–§7 есть в `Russian.json` и `English.json` под `Combat.Panel.*`. Отсутствующий ключ ломает тест локализации. В коде нет литералов «R», «σ», «>», « !», «/3».

## 11. Тесты, которые могут сломаться

- Тесты текста панели аппаратов (US0011, US0013 EP-0012): меняются формат строк профилей, разброса и статуса.
- Тесты, где первый вход в прицел ожидает профиль `slow`.
- Тесты раскладки панели команд и приоритета раскрытия (US0020-TK0002).
