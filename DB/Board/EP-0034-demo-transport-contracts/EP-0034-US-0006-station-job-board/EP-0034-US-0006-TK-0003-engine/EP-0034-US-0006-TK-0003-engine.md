## Implementation steps

1. Формировать не более 6 предложений на станцию за календарные сутки в отдельном named RNG stream. ID = station + publication bucket + index; сохранять выпущенный список и expiry, не пересоздавать по refresh UI.
2. A-01: предложение живёт 2 календарных суток; deadline принятого заказа отдельно начинается при принятии. Оплата = base + distanceRate × frozen routeDistance с коэффициентом urgency и опубликованного risk, округление вверх до целого Tokens; коэффициенты из content, не из UI.
3. Генерировать только достижимые stationIds текущего кластера, feasible payload. Типы Passenger, UrgentPassenger, Cargo; Bounty добавляет EP-0036. Журнал включает Active/Completed/Failed/Cancelled и привязанные offerId/contractId.
4. Обновлять предложения по calendar tick, а не реальному времени; stale offer acceptance отклонять. Общий журнал доступен в полёте и на станции через один projection.
5. Сохранить state, identity counters и receipts в соответствующем typed разделе DemoCampaignData; зарегистрировать handler/tick/projection через hooks EP-0032-US-0007. Duplicate commit и save/load не повторяют расходы, выплаты или события.

## Served acceptance criteria

## Execution result (2026-11-17)

Status: implemented; **validation pending at story end**. No story PASS is claimed here.

Changed files:

- `src/DeepSpaceSaga.Engine/SimulationEngine.StationJobs.cs` — new. `PublishStationJobs` (idempotent per calendar bucket = `gameTime / publicationGameTimeMs`): drops expired offers, then publishes the current bucket once for every cluster station whose role has a filter, up to `limits.offers` live offers per station. Each slot uses the named stream `station-jobs/v1:{station}:{bucket}:{slot}` derived from `MasterSeed` (`RngStreamSeedDerivation` + `RngStreamNames.CreateDeterministicRandom`). Offer id `jobs:{station}:{bucket}:{slot}`. Destinations are direct route neighbours from the current voyage map (cluster stations only, known risk profile). Frozen terms: whole-km route distance, ETA at the carrier speed, deadline duration = max(minimum, ceil(ETA × deadline‰)), payout = ceil((base + load + perKm × km) × urgency‰ × risk‰ / 10⁶). Feasibility by carrier design (passenger cabins = total − crew − reserved, hold capacity); the first publication guarantees an ordinary passenger offer (3 people) on the shortest route from the start station. `StationJobBlocker` is the single acceptance rule (expired, carrier missing/destroyed, not docked at origin, US-0001 life-support/cabin blockers minus passengers promised by Active obligations, free hold minus promised cargo; bounty → `unsupported` until EP-0036). `PrepareStationJobsCommand` handles `AcceptJobOfferCommand`: offer → `Active` obligation `contract:{offerId}`, deadline = acceptance time + duration, offer removed; no money moves. `BuildStationJobsProjection` returns all live offers, the journal, the dock and per-offer verdicts (docked or in flight).

The single-implementation partial hooks stay untouched (EP-0033 implements them).

Assumptions:

- A-01 (from the card): an offer lives 2 calendar days; the obligation deadline starts at acceptance. Missed buckets (long jumps of time) publish only the current bucket; older offers expire by their own time.
- A-02 (technical): command dispatch and calendar publication use explicit calls instead of the single-implementation partial hooks (`PrepareDemoCampaignCommand`/`TickDemoCampaignSections`/`ValidateDemoCampaignSections`), which EP-0033 implements in its branch (see US-0001 A-01). Load validation is a static part of `DemoCampaignData.Validate`.
- A-03 (technical): publication time is the bucket start, independent of when a snapshot observes it; distances are taken from the cluster voyage map at the publishing tick and frozen in whole km (cluster groups move rigidly, so pairwise distances are stable). Campaign "now" is `max(clock, last campaign tick)`.
- A-04 (technical): acceptance in this story only records the obligation; boarding, sealed cargo, payout on delivery (US-0002/US-0004) and Completed/Failed/Cancelled transitions (US-0002/US-0003) are added by their owning stories on top of this journal. Until then Active obligations reserve cabins/hold space in the acceptance rule.
- A-05 (technical): no save-format bump: `stationJobs` is an optional section of `demoCampaign` (schema 1); older demo saves publish the current bucket on the first tick after Load (A-P2 not triggered).
