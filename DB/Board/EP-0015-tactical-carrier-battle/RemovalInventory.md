## Compile order and test disposition

Start from topmost consumers and leave an inactive lower layer intact until its ticket. Partial classes are not independent projects: for each deletion update its direct callers and test fixtures in the same compilable slice. Keep a still-referenced declaration until its last caller is migrated. For shared test files remove only obsolete branches; retain and adapt ordinary navigation, catalogue, loadout, save, clock, dialogue, station, economy and TacticalBattle assertions. Exact added files/test deletions and rationale go into each card before production edits. Keep Engine/Client production layers separate where possible; any unavoidable compiler dependency is recorded explicitly.

Before any legacy schema or content deletion, verify actual Default Save18 and Save19 fixtures (idle and combat) and the previous catalog identity. Do not reinterpret version 19 as version 20 by changing only a version field. Terminal old combat saves never become tactical modal saves; no tactical session data belongs in Save20.
