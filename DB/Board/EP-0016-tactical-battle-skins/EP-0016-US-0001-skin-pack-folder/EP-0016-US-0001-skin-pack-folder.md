# Папка со скинами пошагового боя

## Входное техническое задание

Выполняет требование о папке со скинами и задаёт способ описать все визуальные роли экрана из [эпика](../Documentation.md#что-покрывает-скин).

## User story

Как автор скина, я хочу положить пакет оформления в выделенную папку, чтобы игра обнаружила его без пересборки. Я хочу описать визуальные параметры и ресурсы всего окна боя в одном пакете. Как игрок, я хочу, чтобы при отсутствии или повреждении пакета игра могла открыть бой со штатным оформлением.

## Dependencies

Нет.

## Completion evidence

- Корректный пакет, скопированный в папку по инструкции, обнаруживается при следующем запуске игры и доступен под своим именем и стабильным идентификатором.
- Описание формата и рабочий пример позволяют изменить свойства разных групп оформления и подложить графический ресурс из пакета. Формат покрывает визуальные роли, перечисленные в эпике.
- При проверке отсутствующего, повреждённого или несовместимого пакета, недоступного ресурса и конфликта идентификаторов можно определить причину ошибки. Исправные пакеты и штатный скин остаются доступными.

## Gaps and backlog

Пересканирование после запуска и локализация имён внешних пакетов отложены. Назначение торпедных ролей ограничено текущими боевыми данными, см. G-01 эпика.

## Acceptance criteria

- **US1-AC1.** Версионированный манифест принимает все типы визуальных параметров из схемы v1 и допускает частичное переопределение Classic. Есть машиночитаемые тесты типов, диапазонов, опечаток в свойствах и ссылок.
- **US1-AC2.** В build и publish есть рабочий contrast с PNG. Пакет, скопированный в папку по инструкции, находится при следующем запуске независимо от рабочего каталога. Автор может подготовить новый пакет без пересборки.
- **US1-AC3.** Classic и другие корректные пакеты доступны при отсутствии папки, конфликте ID, неверном JSON, версии, пути или недоступном/повреждённом ресурсе. По диагностике можно найти виновный пакет и поле или файл.

## Non-goals

## Контракт пакета v1

В исходниках поставляемые пакеты лежат в `src/DeepSpaceSaga.Client/Skins/<folder>/`. В build/publish корень — `Path.Combine(AppContext.BaseDirectory, "Skins")`. Подпапка пакета содержит `skin.json` и при необходимости `assets/`. Пользовательские пакеты копируются в тот же корень. Сканируется один уровень, один раз при запуске. На Windows и Linux используются одинаковые правила имён и сравнение ordinal.

```json
{
  "schemaVersion": 1,
  "id": "example-skin",
  "displayName": "Example skin",
  "roles": {
    "field.background": { "fill": "#0B1631", "image": "assets/field.png" },
    "field.grid": { "stroke": "#4E729C88", "strokeWidth": 1.5, "dash": [3, 4] },
    "field.unit.drone.own": { "fill": "#D7A74B", "shape": "diamond", "size": 13 },
    "shot.trail": { "stroke": "#FFCC6688", "strokeWidth": 2.5 },
    "control.label": { "text": "#ECEFFF", "fontSize": 15 }
  }
}
```

| Поле | Тип и правило |
|---|---|
| `schemaVersion`, `id`, `displayName`, `roles` | Обязательные поля. Версия — целое 1. ID — ASCII kebab-case `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$`, 1–64 символа, `classic` зарезервирован. Имя — непустая строка после trim, до 80 символов, без управляющих символов. `roles` — объект, до 512 ролей. |
| Имя роли | От 1 до 128 символов. Сегменты в lower ASCII, разделитель — точка. Сегмент начинается с буквы и допускает цифры и дефисы. Неизвестная роль не влияет на текущую версию, что позволяет объявить роли торпед. Полный поддерживаемый набор и проверка использования — в [US-0002](../EP-0016-US-0002-migrate-battle-rendering/EP-0016-US-0002-migrate-battle-rendering.md). |
| `fill`, `stroke`, `text` | Строки `#RRGGBB` или `#RRGGBBAA`, альфа последняя. |
| `opacity`, `strokeWidth`, `size`, `fontSize`, `radius` | Конечные числа. Opacity от 0 до 1, strokeWidth от 0 до 32, size от 1 до 512, fontSize от 6 до 64, radius от 0 до 128. Размеры в логических пикселях до UI scale. Renderer ограничивает фактический рисунок существующими безопасными границами. |
| `dash`, `shape` | Dash — массив из 0 либо 2, 4, 6, 8 положительных длин от 0.25 до 128. Пустой массив явно задаёт сплошную линию. Shape для поддерживающих ролей — `native`, `circle`, `diamond`, `triangle`, `hexagon` или `square`. |
| `image`, `font` | Относительный путь с `assets/`, разделитель `/`, длина до 240. Простой ASCII-путь с сегментами из букв, цифр, точки, дефиса и подчёркивания. Сегменты `.`, `..`, корневые пути, диски и ссылки запрещены. Image — PNG, font — TTF/OTF. |
| `metrics` | Объект именованных визуальных скаляров. Ключ в нижнем kebab-case. Значения конечные от −256 до 512, дополнительное ограничение зависит от назначения. Применяются только документированные имена. |

Лимиты чтения v1 — 256 КиБ для JSON, до 32 уникальных ресурсов на пакет, до 8 МиБ на ресурс и до 32 МиБ закодированных данных на пакет. Для PNG до декодирования проверить положительные размеры, максимум 4096 по стороне и максимум 4 194 304 пикселя. Сумма декодированных PNG на пакет ограничена 8 388 608 пикселями. Недекодируемое изображение или шрифт отклоняют пакет. Имя расширения сравнивается без учёта регистра. Неизвестное свойство внутри роли, дубли ключей и неизвестное поле верхнего уровня считаются ошибкой формата.

Для каждого свойства выбор идёт от точной роли к её родительским ролям и к штатному значению. Пропущенное свойство наследуется. Штатные процедурные формы и активы сохраняются. Если пакет задаёт изображение, масштабирование/обрезка происходит внутри bounds визуальной роли. Если выбранный шрифт не содержит используемые глифы, для соответствующего текста используется штатный шрифт. Роли разных групп не меняют смысл данных и могут переопределяться независимо.

## Порядок работы для автора скина

1. Скопировать поставляемый `Skins/contrast/` в новую подпапку. Назначить уникальные `id` и `displayName`. Положить изображения и шрифты в `assets/`, обновить ссылки.
2. Разнести предоставленный дизайн по карте ролей US-0002. Частично оформленные роли унаследуют недостающие свойства от Classic. Для завершённой поставки проверить карту на всех состояниях, которые затрагивает дизайн.
3. Перезапустить клиент после изменения файлов, выбрать скин в настройках и открыть бой. Сравнить одинаковые сцены с Classic. Отдельно проверить движение, стрельбу, залп, все вкладки, итог и подтверждение выхода.
4. Передать манифест, используемые ресурсы и список проверенных состояний. Для торпед отмечать наличие данных и результат фактической демонстрации отдельно.
