# EP-0030 — Глобальная дебаг-консоль

Оператор открывает консоль сочетанием Ctrl+Alt+P из любого экрана приложения и управляет ходом программы текстовыми командами. Первая игровая команда — `exit_battle`: закрыть обучающий бой и перейти на экран солнечной системы.

Вторая команда — `kill_drone name`: уничтожить в текущем бою дрона или тэга по имени.

## Grounding

- `DB/Documentation/01-Requirements/EngineRequirements.md:11` закрепляет авторитет Engine над миром и исходами; `:45` требует проверки команд и отсутствия повторных эффектов. Дебаг-консоль не разрешает клиенту напрямую менять authoritative state.
- `src/DeepSpaceSaga.Client/UI/KeyboardEdgeTracker.cs:9` содержит перечень опрашиваемых клавиш; P отсутствует в StandardKeys. Модификаторы собираются перед действиями в конструкторе `KeyboardEdgeTracker(...)`.
- `src/DeepSpaceSaga.Client/UI/SkiaWindow.cs:732` — общий обработчик `HandleKeyboardEvent(Key key, bool repeat)`; текущий экран получает `OnKeyDown`.
- `src/DeepSpaceSaga.Client/UI/SkiaWindow.cs:834` ограничивает переходы из модального боя. Глобальная доступность консоли должна учитывать эти ограничения, а не зависеть только от клавиш отдельного экрана.
- `TacticalBattleFlow.ExitAsync()` в `src/DeepSpaceSaga.Client/UI/Screens/TacticalBattle/TacticalBattleFlow.cs` закрывает бой через сессию и обрабатывает повтор записи checkpoint. При ошибке записи сохраняется `CheckpointPending`; навигация не должна терять результат.
- `src/DeepSpaceSaga.Engine/SimulationEngine.TacticalBattle.cs:138` — `ExitTacticalBattle(ExitTacticalBattleRequest request)`; незавершённый бой получает `SortieExitKind.Aborted` (`:151`), затем выполняется settlement (`:152`).
- `src/DeepSpaceSaga.Client/UI/SkiaWindow.cs:912` — выход из незавершённого обучения в главное меню сначала сохраняет результат; `:920` вызывает `RecordAbandoned()`.
- [EP-0027](../EP-0027-tutorial-start/Documentation.md) запрещает обычный выход на карту до конца обучения. D-03 этого эпика вводит явное исключение через дебаг-команду; обычные кнопки и Esc сохраняют прежний контракт.
- [EP-0028](../EP-0028-battle-tutorial/Documentation.md) описывает подсказки и журнал обучения; при прерывании их lifetime должен завершаться вместе с боем.
- [EP-0029](../EP-0029-unified-carrier-and-torpedoes/Documentation.md) требует постоянных потерь и расхода торпед. Несмотря на старый статус планирования в его metadata, текущий исходник уже содержит settlement: реализацию проверять по коду, не по историческому статусу.

## Предлагаемый объём и ограничения

1. Глобальный overlay консоли с текстовым вводом, выполнением по Enter и видимым результатом/ошибкой.
2. Команда `exit_battle` без аргументов для активного обучающего боя, включая паузу, фазу хода, анимацию и открытый диалог внутри боя.
3. Команда `kill_drone name` для уничтожения именованного дрона или тэга в активном бою, включая учебный и обычный бой.
4. Справочные команды `help` (все зарегистрированные команды) и `list_units` (участники текущего боя); два тикета в US-0004.
5. Подключение будущих именованных команд без переписывания пользовательского поведения консоли. Команды кроме `exit_battle`, `kill_drone`, `help` и `list_units` в этот эпик не входят.

«Из любого места» означает каждый экран и внутреннее модальное окно работающего приложения с фокусом: главное меню без сессии, выбор сценария, карта, меню, настройки, корабль, станция, сохранение/загрузка, бой и его окна. Это не системная горячая клавиша вне приложения и не обещание работы при зависшем UI-потоке. Во время асинхронного перехода оболочка доступна, но команда изменения состояния должна получить понятный ответ «переход выполняется».

### Предложения для review

- **A-01:** Ctrl+Alt+P переключает видимость, Esc закрывает только консоль. Один физический нажим даёт одно переключение; левый и правый Ctrl/Alt равноправны; русская раскладка не мешает сочетанию физической клавиши P.
- **A-02:** открытие консоли само по себе не меняет паузу/скорость. Консоль забирает ввод; клавиши и клики не проходят к нижележащему экрану. При закрытии восстанавливается корректный фокус, без застрявших команд управления.
- **A-03:** Enter выполняет одну строку; пробелы по краям игнорируются, пустая строка ничего не делает. Неизвестное имя команды и неверные аргументы дают ошибку без изменения состояния. Поддерживаются точные имена команд `exit_battle`, `kill_drone`, `help` и `list_units`; shell, скрипты и произвольное исполнение кода не предоставляются. `exit_battle` не принимает аргументы; у `kill_drone` остаток строки после имени команды — имя цели, включая внутренние пробелы.
- **A-04:** успешный выход закрывает консоль и все окна боя, открывая карту той же сессии. Прерывание не считается победой или прохождением всех уроков, не восстанавливает потери и боезапас. Карта получает штатные возможности после закрытия боя, включая сохранение.
- **A-05:** повторный Enter во время выполнения не создаёт вторую операцию. Ошибка завершения/checkpoint оставляет интерфейс восстановления и понятный результат; повтор не дублирует settlement. Поздний ответ старой сессии не меняет новую сессию.
- **A-06:** вне обучающего боя команда отвечает «Нет активного обучающего боя» и ничего не меняет, включая обычный бой по F8. Консоль доступна в обычном запуске клиента без отдельного обязательного флага сборки; это предложение требует review US-0001.
- **A-07:** `kill_drone` ищет точное отображаемое имя цели после удаления краевых пробелов (без нечёткого поиска и подстрок). При совпадении нескольких целей ничего не уничтожается; выводится ошибка неоднозначности. Команда действует на своих и вражеских дронов/тэгов; носители не входят в её область. Детальная семантика — US-0003, пока draft.
- **A-08:** принудительное уничтожение авторитетно обрабатывается Engine, обходит бросок попадания, броню и щиты, не расходует выстрел/торпеду и не продвигает ход. Обычные последствия уничтожения, проверка исхода боя и дальнейшее сохранение потерь действуют; команда не является визуальным удалением объекта.

## Открытые вопросы, риски и gaps

- **G-01:** переход при уже погибшем носителе. В `SkiaWindow.cs:832` действует `EnsureShipDestroyedScreen()`. Нужен продуктовый выбор в review US-0002: карта для осмотра без воскрешения либо сохранение штатного экрана гибели как исключение из D-03. Не обходить guard молча; до решения история не implementation-ready.
- **G-02:** полный перечень экранов для native-приёмки уточняется при декомпозиции; глобальный контракт не ограничивается двумя демонстрационными экранами.
- **G-03:** нормативные документы и существующие Board-эпики не изменены. При реализации явно документировать дебаг-исключение из обычного tutorial gate.
- **G-04:** перед декомпозицией US-0003 установить точное соответствие термина «тэг» боевому типу и источнику отображаемого имени. В текущем коде `TacticalUnit.Id` и `TacticalDrone.PilotName` — разные поля (`src/DeepSpaceSaga.Engine/TacticalBattle/TacticalBattleState.cs:20,48`), а `src/DeepSpaceSaga.Client/Data/Locale/Russian.json:190` употребляет «тэга» в подписи прогноза противника. Эти данные не доказывают, что имя пилота является именем цели; не подменять запрос поиском только по пилоту или внутреннему ID.
- Риск: потеря ввода/фокуса поверх модальных окон, повторная обработка Enter, навигация до записи checkpoint, перенос команды в другую сессию.

- US-0001: автоматические проверки сочетания, repeat, фокуса, парсинга и изоляции ввода; native-проверка разных экранов, модальных окон и RU/EN раскладок.

- US-0003: проверить свои/вражеские цели, дрона/тэга, имя с пробелами, отсутствующее/неоднозначное имя, уже уничтоженную цель, отсутствие боя, повтор команды, смену сессии, паузу и разные фазы. Отдельно проверить последнего противника, обновление очереди/карточек/карты, отсутствие выстрела и RNG-расхода, сохранение потери после `exit_battle`.
