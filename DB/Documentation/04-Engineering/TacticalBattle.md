# Тактический бой носителей

Бой — временная сессия, запущенная с карты мира через [подготовку](../02-FirstRelease/Screens/TacticalBattleSetup.md). Engine принимает запуск только на паузе (Speed0). Состояние сражения, приказы, потери и журнал не входят в Save20. Возврат восстанавливает карту и скорость мира, включая случай проигрыша. [Сохранения](SaveFormat.md) описывают границу персистентности.

| Слой | Ответственность |
|---|---|
| Contracts | Неизменяемые параметры сценария, запросы Start/Move/Fire/Exit, ревизия, результаты, журнал и снимок |
| Engine | Валидация каталога, сборка боя, алгоритмы тактик, приказы, броски Mulberry32, урон, потери и победа |
| Motion | Общая тактическая геометрия, кинематика движения, углы, пределы, вероятность и совместимая численная арифметика |
| LocalClient | Передача запросов сессии; отдельная ветка от снимков мира |
| Client | Ввод, черновики приказов, прогноз, анимация и представление допущенного снимка |

Базовые данные собираются из [V4 Data](../../../VData/Planning/V4.0/Data/) в [Data/TacticalBattle](../../../src/DeepSpaceSaga.Client/Data/TacticalBattle/). Расширение initiative хранится в runtime pilots.json и присоединяется экспортёром по ordinal ID. Исторические [V4 Spec](../../../VData/Planning/V4.0/Spec/) и Reference описывают прежний одновременный залп; актуальные правила инициативы определены ниже. Доступность каталога публикуется отдельно; отказ содержит файл, поле и сообщение и не мешает загрузке обычного мира.

`StartTacticalBattleRequest` выбирает сценарий, целочисленный seed, тактики и допустимую комплектацию. `MoveTacticalBattleRequest` содержит только отредактированные приказы; прочие дроны выполняют предложение тактики. Engine ограничивает скорость и угол по текущей массе, двигателям и инерции. `FireTacticalBattleRequest` передаёт цель, отсутствие выстрела или Evade для каждого своего дрона. При отсутствии целей Engine может обработать фазу автоматически.

## Инициатива и порядок стрельбы

Каждый пилот имеет обязательную initiative: целое 0…100 либо массив [min,max] с целыми границами 0…100 и min ≤ max. Неизвестные/повторные поля, дроби, строки, null и неполный диапазон недопустимы. Вера=55, Юн=53, Марта=59, Олег=50; таги материализуют диапазон [40,55] один раз при сборке. Значение не зависит от Accuracy и сохраняется до конца временного боя.

Основной Mulberry32 сохраняет прежний порядок сборочных draws. Отдельный InitiativeRandom получает seed `uint(seed) ^ 0x494E4954`: фиксированное значение не расходует draws, диапазон расходует один, включая вырожденный. После materialization Engine один раз проходит группы инициативы по убыванию и выполняет Fisher–Yates внутри равных групп (n−1 draws). Полученный ранг стабилен между ходами. Массив Drones не переставляется; очередь фильтрует неактивных. Capture и forecast не расходуют RNG. RandomCalls исхода учитывает основной stream.

До разрешения Engine замораживает цели обеих сторон, валидирует весь пакет приказов и только затем выполняет Dry, статистику и draws. Общая очередь обеих сторон идёт по убыванию инициативы и стабильному рангу. Для каждого слота приоритет причин пропуска: BattleEnded; ShooterDestroyed/ShooterDisabled; Evading; InDust; WeaponJammed; NoTarget/Withheld; TargetUnavailable. Пропуск не делает выстрела и не расходует его RNG. Потерянная цель не заменяется новой.

После каждого фактического выстрела немедленно применяются броня, корпус, статус, повреждения систем и статистика; SoloHullLoss учитывает фактически снятый корпус. FirstLoss следует хронологии. Победа проверяется после шага: при её достижении дальнейшие боевые действия прекращаются, остальные слоты получают BattleEnded. Уничтоженный, выведенный из строя или получивший jam стрелок теряет ответный выстрел в этой фазе.

## Уклонение и сознание

Источник параметров — [rules.json](../../../src/DeepSpaceSaga.Client/Data/TacticalBattle/rules.json), блоки consciousness/evasion: start/max100, recoveryPerTurn5, hitPenalty20, cost/minConsciousness10, aiHullFraction0.5. Consciousness хранится в TacticalDrone и nullable DTO (носитель null). Восстановление выполняется один раз в Planning при Turn>1 только для IsActive, с ограничением max; Capture/forecast/replay ничего не восстанавливают.

TacticalFireTarget.Evade по умолчаниюfalse; совмещение с TargetId возвращает InvalidRequest, недостаточное сознание — EvasionUnavailable; оба отказа атомарны. Engine фиксирует планы всех активных стрелков, списывает цену у всех уклоняющихся и затем разрешает очередь. Смерть до своего слота не отменяет цену. Приоритет BattleEnded/destroyed/disabled выше Evading; собственный выстрел и его RNG не выполняются. AI DefaultPlan использует строго Hull < aiHullFraction×MaxHull и Consciousness≥minConsciousness. Пропущенные приказы игрока означают Hold.

Motion вычитает hitPenalty после щитов перед clamp min/max. Incoming.ChanceIfEvading вычисляется тем же pure-путём; клиент не придумывает новый штраф. Session открывает Fire при любом собственном кандидате либо кандидате врага на своего дрона; carrier-only атака врага остаётся автоматической. Ввод E фиксирует текущий выбор до Submit; противник раскрывает EV в SalvoFlight, до этого прогноз не выдаёт его приказ.

Согласованный production штраф 20 сохраняется: калибровка измеряет эффект и докладывает в Board, не изменяя баланс автоматически. Текущие правила заменяют одновременную модель исторического V4 только в перечисленных расширениях.

## Ловушки

Модуль [decoy.t1](../../../src/DeepSpaceSaga.Client/Data/TacticalBattle/Modules/Decoys/decoy.t1.json) задаёт tier1, charges2, missFactor1.5 и massKg10. moduleSlots у light/heavy/thug равен 1, у carrier0; layout.module может отсутствовать/null. Каталог строго проверяет ссылки, слоты, типы и конечность чисел. Масса модуля входит в Limits независимо от оставшихся зарядов; повреждение систем модуля не вводится.

TacticalFireTarget.Decoy=false по умолчанию. Decoy+Evade возвращает InvalidRequest, отсутствующий/истощённый модуль — DecoyUnavailable, весь пакет отклоняется до изменений. После проверки планов оба выбора фиксируются; заряд уменьшается даже если стрелок впоследствии погиб или по нему не стреляли. AI использует frozen планы и EV-adjusted incoming probability до D (и с текущей геометрией поля): достаточно одного планируемого выстрела≥rules.decoy.aiThreatChance (0.4). Direct AI управляет обеими сторонами; Session только вражеской, свои omitted приказы не включают D.

Для первого фактического выстрела в цель применяется `max(hit.minChance/100, 1 − missFactor × (1 − conditionalChance))`. conditionalChance уже ограничен и учитывает EV/щит; термопоглощение применяется отдельно. Счётчик D удаляется перед absorption draw, поэтому даже поглощённый снаряд расходует эффект. Пропуск shooter/target не является выстрелом и не снимает эффект. Пуск без входящих выстрелов истекает в конце залпа, заряд не возвращается; нет самостоятельного RNG пуска.

DecoyCharges nullable у носителя; Build публикует DecoyId/Name/MaxCharges. Salvo.DecoysLaunched фиксирует пуски, Shot.Decoyed и ChanceWithoutDecoy — только реально затронутый выстрел, журнал содержит DecoyLaunched. ChanceIfDecoy в Incoming — прогноз первого воздействия. До SalvoResults клиент скрывает D противника, его новый расход и связанные лог/shot hints; свой расход виден сразу после принятия. Скрытие не меняет authoritative исход.

## Аномалии

Источник — anomalies в [rules.json](../../../src/DeepSpaceSaga.Client/Data/TacticalBattle/rules.json). zoneEdge170 строго выше background100; absorbSamples200. heatCount[1,3], dustCount[1,2], clumps[6,10] — включительные целые диапазоны. spread[40,55], clumpAmp[70,160], clumpSigmaX[0.18,0.34], clumpSigmaY[0.14,0.26] — вещественные диапазоны; sigma умножается на spread. centerSpread[0.45,0.35] — вектор X/Y, не диапазон. clearance60, bandFraction0.6, maxAttempts64, aiDustSearch4. Loader строго проверяет числа, границы и неизвестные поля; старый payload без Anomalies означает пустое поле.

TacticalAnomalyGenerator использует Mulberry32 с low32 от DeriveStreamSeed(uint64(seed), "tactical-anomalies"). Он не расходует основной или initiative RNG. Сначала выбирает оба количества, затем все Heat, затем Dust. X anchors лежат в средней bandFraction полосе между средними X дронов сторон; Y — в диапазоне стартовых Y дронов. Затем генератор добавляет до шести периферийных аномалий в двух рядах с тройным делением по X вдоль всей линии развёртывания. Отступ рядов от стартовых Y составляет 2–3 максимальных spread. За ближними областями внешняя сетка 4×4 добавляет по одному центру в 12 крайних секторах, включая углы. Ширина клетки равна ширине развёртывания или четырём максимальным spread, если развёртывание уже. Периферийные центры разделены как минимум двумя минимальными spread, а сгустки имеют те же размеры, что и в центральной полосе. До 64 попыток на anchor: расстояние до каждого старта дрона/носителя≥clearance; при неудаче аномалия пропускается. Это ограничение anchor, не обещание отсутствия всех Gaussian хвостов у старта. После spread/clumpCount каждая пара Box–Muller задаёт смещение центра через centerSpread, затем amplitude/sigmaX/sigmaY/rotation[0,π]. Snapshot содержит immutable clumps (мировые sigma, rotation радианы), anchor — только диагностический state генератора.

Motion вычисляет `background + Σ amplitude×exp(−0.5×((u/sigmaX)²+(v/sigmaY)²))` с поворотом в локальные u/v. Все clumps одного вида суммируются до threshold, каждый sample учитывается один раз. Inside использует≥zoneEdge. Absorption=Ninside/N с midpoint t=(i+0.5)/N на прямой от стрелка до цели; Segments объединяет соседние inside samples в интервалы[i/N,j/N]. Нулевая длина использует ту же midpoint семантику. Аналитический градиент нужен только представлению, не боевому штрафу.

Candidates публикует final Chance=conditionalChance×(1−Absorption), в том числе по носителю. У фактического выстрела D применяется к conditionalChance, затем при Absorption>0 выполняется absorption draw до hit. Поглощённый выстрел считается shot/absorb, без hit/damage/rear/system draws; при Absorption0 дополнительного draw нет. Fields не меняются от Move, EV и D не заменяют absorption probability. InDust фиксируется в плане перед залпом; skip priority теперь BattleEnded, destroyed/disabled, Evading, InDust, jam, no-target/withheld, target-unavailable.

TacticalDustAvoidance выполняется после исходного AI плана: если proposed endpoint в пыли и гипотетические candidates без dust gate непусты, ищет углы order ±k×limit/aiDustSearch (+ затем−), скорости order/min/max с обычными acceleration/turn clamps. Первая безопасная альтернатива принимается; иначе остаётся исходная. Сам поиск не тратит RNG и не меняет юнит при гипотетической оценке. При непустом поле выбор цели упорядочен по final Chance, затем прежним role/distance; пустое поле сохраняет прежнюю семантику.

Snapshot публикует Anomalies/Rules.Anomalies, Unit.InDust, Candidate/Incoming/Shot.Absorption и Shot.Absorbed; лог ShotAbsorbed и skip InDust типизированы. Client использует те же Field/Segments/Inside для визуализации. В активном окне слой аномалий повторно проецирует текстуру в мировых координатах при движении камеры. Быстрый предварительный растр закрывает новую область, а после стабилизации камеры один фоновый расчёт уточняет изображение. Синхронный растр для проверок использует ту же формулу и кэш по clumps, rules, camera, size и scale. Procedural texture/gradient/shading — только внешний вид; conservative bounds отбрасывают лишь математически чёрные вклады по UiSpec. Поле Screen-composite, без контуров, с heat/dust hover и heat отрезками линии огня. Рендер не расходует RNG и не влияет на исход.

## Слоты и карточка сборки

TacticalUnitSnapshot.Slots (по умолчанию пусто) и Build.EngineSlots/ModuleSlots (по умолчанию 0) добавляются совместимо к прежнему payload. SnapshotBuilder проецирует порядок: Weapon0, Armor0, Shield0…ShieldSlots−1, Engine0…EngineSlots−1, Module0…ModuleSlots−1. У носителя Slots пусты. Отсутствие установленного предмета задаётся ModuleId=null/ModuleName=null, State=Ok, Factor1; каталоговая armor.none остаётся установленной записью с прежним ArmorId. Jammed у оружия отражает текущий jam; Damaged у двигателя — Factor<1, прочие слоты Ok. Исчерпание зарядов не удаляет модуль.

BuildCardModel использует Slots как единственный источник наличия предмета и состояния; Build/Engines/Limits дают только уже рассчитанные числа. Неизвестная FrameId получает light силуэт. Модель и отрисовка не меняют приказы, сборку, RNG или выбор. Сначала показывается свой дрон под курсором; чужой/носитель/аномалия временно используют прежнюю hover card. Без hover в Move/Fire берётся выбранный; в SalvoFlight — активный свой стрелок, иначе captured LastSelectedDroneId; в Results — свой стрелок показанного выстрела, без него последний выбранный. В итоговом Over без Salvo карточки своей сборки нет. LastSelectedDroneId хранит UI selection отдельно от SelectedDroneId, который намеренно null в Salvo.

Схема карточки — [UiSpec EP20](../../Board/EP-0020-tactical-battle-mechanics/UiSpec.md)§22–26:300design units под правой панелью, три силуэта, заполненные/пустые/отсутствующие ячейки, красные повреждения, масса/движение. Весь прямоугольник занят для map labels и input hit-testing. Имена и строки слотов обрезаются посимвольно с многоточием при неизменном размере шрифта; измерение выполняется BattleTypography. R/A/B/C округляются ToEven до целого, угол двигателя/поворот максимум 1 знак, Factor максимум 2 без лишних нулей, скорость/разгон F1. RU использует запятую, EN точку. Редактирование и сборка противника отсутствуют.

## Снимки и воспроизведение

Contracts добавляет nullable Initiative для совместимости старых payload и FireQueue/FireSteps с пустыми значениями по умолчанию. Queue доступна до Fire. После Fire один immutable FireStep соответствует каждому слоту: индекс, стрелок/цель, выстрел или skip reason, события, полный UnitsAfter и outcome на решающем шаге. Killed означает lethal impact конкретного выстрела. Значения старых log kind 0…13 сохранены, FireSkipped=14, DecoyLaunched=15, ShotAbsorbed=16. Лента сохраняется при переходе к следующему Planning и очищается следующим Move.

Client хранит Before/After, но карта, карточки, заголовок, результаты и журнал читают одну допущенную Project-проекцию. До попадания состояние и outcome будущих шагов скрыты. Начальная задержка 300 ms; длительность каждого из N фактических выстрелов min(975,4200/N) ms, вся последовательность не более 4500 ms. Попадание включается на границе времени; вспышка 450 ms может перекрываться со следующей. Пропуски не создают фиктивные снаряды; при N=0 публикуется итог сразу. Skip и replay меняют только представление, без запроса и RNG. Повторный ответ не запускает анимацию повторно; отказ с новым live state сбрасывает устаревшую проекцию. Старые payload без FireSteps используют совместимый путь.

Снимок публикует общую очередь до Fire. Новый UI показывает инициативу в карточках и очередь во время залпа; прежние вкладки прогноза/журнала не подключены к активному экрану. Ранний выстрел по-прежнему может отменить поздний. Клиентский прогноз не раскрывает будущую ленту.

Move и Fire проверяют идентификатор боя и ожидаемую ревизию. Engine хранит до 16 последних ответов и освобождает прежние ответы при успешном выходе из боя. Повтор с теми же ID и данными получает сохранённый ответ либо код `ReceiptExpired` без снимка. Команда не применяется повторно в течение жизни Engine. Повторное использование ID для другого запроса возвращает `IdentityConflict`. Актуальный снимок доступен через `GetTacticalBattleState`. В клиентском прогнозе оценки движения и попаданий не потребляют RNG и не меняют приказы без ввода. Наблюдение за кадром или повтор анимации не вызывает Engine.

Client разрешает [скин боя](TacticalBattleSkins.md) при создании активного окна. Каталог и предпочтение относятся к клиенту, отрисовка читает готовые ресурсы под синхронной областью стиля. Save20 хранит состояние мира.

## Клиентская презентация

Макет активного боя — 1280×720, масштаб S=H/720; menu uiScale его не меняет. Карта лежит под панелями. В Classic, Contrast и Xenon Star базовая карточка имеет высоту 82, зазор между карточками равен 5. Выбранная карточка расширяется на высоту блока текущей фазы. Правая панель привязана к правому краю и заканчивается на y=152 в движении и стрельбе. Карточки наведения и сборки начинаются на y=158. Камера использует безопасную область между колонками, а draw и hit-testing переводят координаты через один масштаб. Токены и примитивы заданы в [BattleDesign](../../../src/DeepSpaceSaga.Client/UI/Screens/TacticalBattle/BattleDesign.cs). Геометрию карточки и панели планирования задаёт [UiSpec EP-0023](../../Board/EP-0023-pilot-card-commands/UiSpec.md).

BattleTypography загружает Regular/Bold DejaVu Sans только из UI/Fonts в output. TextPaint использует NoHinting, grayscale antialiasing, SubpixelText и IsLinearText; измерение и рисование совпадают. Отсутствующий файл даёт лог, IsBundled=false и fallback меню; проверка типографики при этом не проходит. SHA исходных TTF и восстановленное происхождение reference записаны в Assets Board. Запасной системный шрифт не является принятым видом боя.

Клиентский Data/UI/tactical-battle-pilots.json связывает pilotId с портретом и родом. Catalog декодирует изображения до отрисовки, неизвестные/повреждённые данные дают fallback; Engine pilots.json и Contracts не меняются. Сознание читается из допущенного снимка; значение по умолчанию 100 предназначено только для совместимости старых payload. PilotCardModel читает текущие приказы и допущенную проекцию, а итоговый урон сопоставляет ShotHit и DamageApplied того же хода.

PhasePanel, PilotCardColumn, HoverCard и BattleMapRenderer читают один TacticalBattleFrame. PilotColumnLayout строится до отрисовки карты. Её видимые прямоугольники используются для кликов, прокрутки и области размещения подписей. Блоки движения и стрельбы регистрируют команды только у выбранного пилота и обрезают зоны по видимой части колонки. Команды повторно проверяют выбранного пилота и идут в TacticalBattleOrders/TacticalBattleFireOrders. Ввод блокируется при Pending, анимации движения, показе залпа и модальном подтверждении. Колесо над переполненным списком целей обрабатывается до колеса колонки. Блок залпа читает допущенный снимок и не регистрирует команд. Hover не вызывает ObserveOrders или session commands; неподвижный курсор переоценивается при новом кадре. Фазы сохраняют прежние ограничения pending, receipt identity, паузу мира и расписание результатов. Камера подгоняется под поле при первом кадре нового боя. Колесо меняет масштаб, а перетягивание правой кнопкой меняет центр. В Classic, Contrast и Xenon Star смена фазы, хода, режима воспроизведения и размера области карты сохраняет центр и масштаб в логических координатах. Tabletop автоматически кадрирует новые фазу/ход до первого ручного pan/zoom; полёт и результаты сохраняют кадр.

Ep0019Scenes строит семь основных реальных сцен seed1 и дополнительные сцены аномалий/сборки через Engine, session и SkiaWindow без native window. Ep0019Acceptance проверяет literal строки, формулы/геометрию и raster probes; Ep0019Snapshots сравнивает PNG с порогом ΔRGB40, общим 0.5% и 25% в блоке 16×16. PNG в тестовом проекте — актуальный production baseline после прохождения независимых проб, не замена проверкам спецификации. Обновление требует решения Board; флаг DSS_EP0019_ACCEPT_SNAPSHOTS разрешён только для такого обновления. DSS_EP0023_PREVIEW_SNAPSHOTS сохраняет кандидатные PNG перед принятием. DSS_VALIDATION_ROOT задаёт абсолютный каталог evidence вне репозитория. Растр не доказывает native input/GPU; оконный workflow описан в [Performance README](../../../tools/DeepSpaceSaga.Performance/README.md).

### Презентация Tabletop

Три независимых opt-in метрики манифеста v1: `field.style.tabletop`, `ui.style.steel`, `ui.pilot-column.slim`, каждая равная 1. Они не привязаны к имени пакета. `TacticalBattleSkinRenderScope` читает готовые ресурсы синхронно; камера получает признак поля явно вне ambient scope. Engine, Motion, Contracts, RNG, расписание FireSteps, command identity и Save20 не меняются.

Карта рисует фон, кэш облаков, сетку, шаблоны/ленты, модели и плашки, затем эффекты/итоговые пометки. Все значки шансов размещаются после лент. Пиксельные модели используют целый масштаб и привязку к пикселям устройства, без повторного декодирования PNG. Прямоугольники плашек, моделей, колонок и правых окон участвуют в размещении подписей и hit-testing.

`PaintedCloudLayer` принадлежит активному экрану. Ключ — полный TacticalBattleView, масштаб холста, значения сгустков и идентичность GRContext. При неизменном ключе переиспользуется SKImage; при смене — один новый кадр. Пересборка отсекает невидимые сгустки по границам повёрнутого эллипса с запасом 4σ размытия и 2 единицы дизайна. Offscreen-слой и шум ограничены объединением видимых границ; шум сохраняет экранное начало координат. Параметры исходного mask blur, цвета и порядок смешивания сохраняются. Native RenderNative передаёт существующий GPU-контекст из SkiaWindow; headless использует CPU surface. Кэш освобождается при уходе с экрана, пустом поле и замене; контекст принадлежит окну. Нет фоновых задач, отдельного RNG или повторной отрисовки облаков внутри сектора. Нормированная альфа шума проверяется числовыми пробами используемого Skia API.

Slim-раскладка строит отдельный VisiblePanel вместе с карточками до карты. Move/Fire регистрируют команды только внутри этой видимой панели. Залп не регистрирует команд. Space без repeat/модификаторов пропускает только полёт при slim=1 и отсутствии confirm/busy; дальнейшие Space остаются блокированными мировыми клавишами. Enter и прежние команды сохраняются. Геометрия правых окон общая со старыми скинами, геометрия левой колонки намеренно отличается.

`TabletopSnapshots` использует настоящий Engine/session/SkiaWindow с изолированным Settings-профилем, восемь сцен seed1 и 1920×1080. `DSS_EP0024_PREVIEW_SNAPSHOTS=1` сохраняет кандидаты, `DSS_EP0024_ACCEPT_SNAPSHOTS=1` принимает их только после просмотра и решения Board. При обычном запуске сравниваются PNG: ΔRGB40, общий порог0,5%, блок16×16 до25%. `TabletopPanelProbeTests` независимо проверяет координаты, цвета и ввод на S1/S1.5. Эталоны Classic не перезаписываются. Методика native GPU timing и ограничения измерения — [Performance README](../../../tools/DeepSpaceSaga.Performance/README.md).
