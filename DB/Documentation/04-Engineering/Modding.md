# Принципы моддинга Deep Space Saga

Цель моддинга DSS — дать авторам возможность добавлять кнопки, окна и собственное поведение через API DSS. Скины задают внешний вид существующего интерфейса. Например, EP-0016 описывает оформление окна пошагового боя, а прототип «Вступить в драку» добавляет действие в диалог и открывает своё окно. [EP-0016](../../Board/EP-0016-tactical-battle-skins/Documentation.md)

Реализация прототипа отложена в локальной ветке `codex/archive-dialogue-modding-prototype`, коммит `84354ac20e380493b96eabd37fdc6678c0c60a91`. Примеры API, сборки и проверки ниже относятся к этому снимку.

| Участник | Ответственность |
|---|---|
| Мод | Определяет, где предложить действие, описывает окно и задаёт обработчики кнопок. |
| Client | Предоставляет точку расширения, создаёт `ModContext` для текущего диалога, рисует виджеты и передаёт команды игровой сессии. |
| Engine | Владеет игровыми данными. Проверяет адресата, контекст и допустимость команды, применяет изменение и публикует результат. |

`ModContext.GetCharacter(id)` выдаёт представление персонажа DSS типа `DssCharacter`. Оно предоставляет имя, чтение HP и метод `AddHitPoints(delta)`. В прототипе контекст разрешает получить капитана и текущего собеседника, а `ModPortrait` выводит портрет, который уже использует экран диалога. Действия с персонажем оформляются командами DSS. Мод читает подтверждённые данные из проекции игры. [Архитектура DSS](../00-Process/CLAUDE.md)

## Как автор описывает окно

Прототип — отдельная C#-библиотека для `net8.0` со ссылкой на `DeepSpaceSaga.ModApi`. Точка входа реализует `IDialogueMod`. Метод `GetButtonLabel(dialogueId, participantId)` возвращает подпись для подходящего диалога или `null`, если кнопку показывать не нужно. Для `dialogue.station-docking` с Mari Lefeber (`CHR-0003`) DSS размещает эту кнопку под портретом собеседника. Нажатие вызывает `Open(ModContext)`.

Автор создаёт `ModWindow` из колонок. Колонки идут слева направо, а виджеты внутри каждой колонки идут сверху вниз. `ModPortrait` показывает персонажа, `ModLabel` вычисляет текст для кадра, `ModButton` задаёт обработчик и может проверять доступность действия. Например, окно драки можно описать так.

```csharp
public void Open(ModContext context)
{
    var player = context.GetCharacter(context.PlayerId);
    var opponent = context.GetCharacter(context.OpponentId);

    context.OpenWindow(new ModWindow("Драка", [
        new ModColumn([new ModPortrait(player)]),
        new ModColumn([
            new ModButton("Ударить", () => opponent.AddHitPoints(-10),
                () => !context.IsCommandPending && opponent.HitPoints > 0),
            new ModButton("Выйти", context.CloseWindow)
        ]),
        new ModColumn([
            new ModPortrait(opponent),
            new ModLabel(() => $"Тестовые HP: {opponent.HitPoints}")
        ])
    ]));
}
```

Полная версия также выводит имена и тестовые HP обоих участников. Исходник в архиве — `tools/DeepSpaceSaga.DialogueBrawlMod/MariBrawlMod.cs`.

## Как удар меняет состояние игры

1. Обработчик в DLL вызывает `opponent.AddHitPoints(-10)`. Client передаёт движку `DialogueCommand` с действием `AdjustCharacterHitPoints`, ID персонажа, величиной изменения, ID диалога, его ревизией и уникальным ID команды.
2. Engine проверяет активный диалог, его ревизию и то, что цель действительно текущий собеседник. Тестовые HP хранятся в игровой сессии по паре «станция, персонаж». Значение начинается со 100 и ограничивается диапазоном от 0 до 100. Engine применяет команду с одним ID однократно.
3. Engine публикует подтверждение и обновлённые HP в `DialogueState.TestHealth`. Кнопка удара ждёт подтверждения, а текст берёт HP из снимка. После одного удара у Мари 90 HP. Закрытие и повторное открытие окна даёт те же 90 HP, как и новый разговор с ней в той же сессии. При загрузке сохранения тестовые HP начинаются заново.

В архиве обработку команды определяет `src/DeepSpaceSaga.Engine/Dialogue/SimulationEngine.Dialogue.cs`, а время жизни HP — `src/DeepSpaceSaga.Engine/Dialogue/DialogueRuntime.cs`.

## Сборка и проверка прототипа

Загрузчик прототипа рассчитан на один доверенный мод. При первом открытии диалога он загружает заранее собранную DLL из `Mods/DialogueBrawl/DeepSpaceSaga.DialogueBrawlMod.dll` рядом с исполняемым файлом клиента и создаёт экземпляр `IDialogueMod`. Сборка клиента из архивной ветки кладёт туда демонстрационный мод автоматически.

API можно прочитать из активной ветки, обращаясь к архивному коммиту.

```powershell
git show 84354ac20e380493b96eabd37fdc6678c0c60a91:src/DeepSpaceSaga.ModApi/DialogueMod.cs
```

1. В архивной ветке из корня репозитория выполните `dotnet build tools/DeepSpaceSaga.DialogueBrawlMod/DeepSpaceSaga.DialogueBrawlMod.csproj`. Чтобы проверить изменение только мода, замените собранную DLL в каталоге загрузчика и перезапустите клиент.
2. Выберите **«Новая игра» → Undocked at Station**. На стартовой паузе выберите **Free Port Aurora IV** и нажмите **Dock** в панели навигации.
3. Нажмите **«Вступить в драку»**, затем **«Ударить»**. Дождитесь 90 HP, нажмите **«Выйти»** и снова откройте окно. Ожидаемое значение — 90 HP.

В архиве эту проверку покрывает `DialogueScreenTests.Mari_mod_changes_engine_health_and_reopening_reads_the_same_90_HP`.

## Обсуждавшиеся возможности для сообщества

- **Именованные точки расширения.** DSS может предоставлять места в штатных экранах, например под портретом, в меню или в панели корабля. Мод регистрирует добавляемый элемент и окно по стабильному ID. Если несколько модов используют одно место, клиент определяет порядок отображения.
- **Описание интерфейса.** Для простого окна обсуждались данные и ресурсы с готовыми виджетами и действиями DSS. Программируемый вариант позволяет автору собрать те же виджеты в C# и написать собственные обработчики. Доступные модам игровые действия определяет API DSS.
- **Каталог пакетов.** Обсуждались отдельные подпапки в `Mods/`, манифест с ID и версиями мода и API, зависимости, включение в настройках и диагностика проблемного пакета.
- **Способ поставки кода.** В прототипе использована готовая C# DLL. Отдельный вариант для распространения исходников — компиляция через Roslyn при загрузке или изменении пакета и повторное использование сборки. Способ поставки отделён от API, которое получает окно. [Документация Roslyn](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.csharp.csharpcompilation)
- **Доверие и изоляция.** `ModContext` задаёт набор доступных игровых операций. DLL внутри процесса получает права этого процесса. Для модов от незнакомых авторов обсуждался отдельный процесс с ограничениями ОС, где вызовы через `ModContext` передаются DSS по протоколу, а клиент по-прежнему рисует окно. [Модель плагинов .NET](https://learn.microsoft.com/en-us/dotnet/core/tutorials/creating-app-with-plugin-support)

Эти возможности описывают обсуждавшееся направление. Архивный пример охватывает доверенный мод диалога и тестовые HP игровой сессии.
