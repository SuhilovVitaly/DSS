# ТЗ: экономика станции, производящие модули и размер станции

Статус: принято как новая техническая постановка, требует реализации.

Источник требований: новая модель станционной экономики от 2026-08-25. Основной источник истины: `deep_space_saga_engine_requirements.md`, раздел 59.

## Цель

Станция должна иметь размер, производящие модули, конечный торговый склад и ценовую модель, в которой базовая цена номенклатуры умножается на все применимые коэффициенты станции и округляется до целого количества `Credits`.

## Термины

- `TradeItem` - любая номенклатура, которую игрок может купить или продать через станционную торговлю.
- `Resource` - сырье/ресурс, например `Ice`, `Iron Ore`, `Silicon`, `Magnesium Ore`.
- `Good` - товар/продукт, например `Food Rations`, `Water`, `Steel`, `Energy Cells`, `Fuel`, `Protein mass`.
- `Module` - покупаемый/продаваемый тип модуля. В торговле учитывается штуками, а не kg.
- `ProducingStationModule` - станционный производящий модуль, который выпускает один или несколько `Good` и требует один или несколько входных `Resource`.
- `BasePriceCredits` - базовая цена единицы номенклатуры до станционных коэффициентов.
- `StationPriceFactor` - любой multiplicative фактор цены станции: размер, потребность в сырье, событие, баф или дебаф.

## Номенклатура

### Resource

Покупка игроком:

- игрок может купить любое целое количество ресурса, если хватает `Credits`, cargo capacity и склада станции;
- купленный ресурс попадает в cargo container и учитывается по массе.

Продажа игроком:

- ресурс продается только упаковками по `100` kg;
- UI должен выбирать количество продажи с шагом `100`;
- Engine должен authoritative отклонять продажу ресурса, если количество не кратно `100`;
- частичная продажа при нехватке `Credits` станции также должна исполняться только целым количеством упаковок.

### Good

Покупка игроком:

- игрок может купить любое целое количество товара, если хватает `Credits`, cargo capacity и склада станции;
- `Fuel` остается специальным случаем: покупается через торговлю/заправку, но попадает в бак двигателя, а не в cargo.

Продажа игроком:

- товар продается только упаковками по `10` kg;
- UI должен выбирать количество продажи с шагом `10`;
- Engine должен authoritative отклонять продажу товара, если количество не кратно `10`;
- частичная продажа при нехватке `Credits` станции также должна исполняться только целым количеством упаковок.

### Module

Покупка игроком:

- игрок может купить любое целое количество модулей, если станционная услуга/склад модулей это поддерживает;
- модульная покупка должна быть отдельной authoritative операцией от cargo-покупки;
- установка купленного модуля на корабль не должна происходить неявно, если отдельная станционная услуга установки не указана.

Продажа игроком:

- модули продаются поштучно;
- UI должен выбирать количество продажи с шагом `1`;
- Engine должен authoritative отклонять нецелое или неположительное количество.

## Стартовая станция

Стартовая станция в стартовом сценарии должна иметь размер `Large`.

Явный начальный склад стартовой станции:

| Категория | Номенклатура | Количество |
| --- | --- | ---: |
| Good | `Food Rations` | `500` |
| Good | `Energy Cells` | `350` |
| Good | `Fuel` | `700` |
| Resource | `Ice` | `320` |
| Resource | `Iron Ore` | `410` |
| Resource | `Silicon` | `70` |
| Resource | `Magnesium Ore` | `120` |

Правило: явный склад стартовой станции имеет приоритет над прежней случайной генерацией `20..500`.

## Размеры станции

Размер станции хранится как explicit enum-значение:

```text
Huge
Large
Medium
Outpost
```

В UI допускаются русские названия:

| Id | UI-имя |
| --- | --- |
| `Huge` | Огромный |
| `Large` | Большой |
| `Medium` | Средний |
| `Outpost` | Форпост |

### Коэффициенты общих ресурсов

Применяются к `Resource`, который есть в продаже/покупке станции, но не является текущим входом производящего модуля станции.

| Размер | Коэффициент |
| --- | ---: |
| `Huge` | `1.20` |
| `Large` | `1.15` |
| `Medium` | `1.10` |
| `Outpost` | `1.00` |

### Коэффициенты потребляемых ресурсов

Применяются к `Resource`, который является входом хотя бы одного активного/доступного производящего модуля станции.

| Размер | Коэффициент |
| --- | ---: |
| `Huge` | `1.30` |
| `Large` | `1.25` |
| `Medium` | `1.15` |
| `Outpost` | `1.10` |

### Коэффициенты товаров

Применяются к `Good`.

| Размер | Коэффициент |
| --- | ---: |
| `Huge` | `1.00` |
| `Large` | `1.10` |
| `Medium` | `1.15` |
| `Outpost` | `1.20` |

Для `Module` коэффициент размера станции пока считается `1.00`, если отдельное решение по модулям не принято.

## Производящие модули станции

Каждый `ProducingStationModule` должен задаваться data-driven конфигурацией:

- stable id производящего модуля;
- display name;
- список выпускаемых `Good`;
- список входных `Resource`;
- коэффициент потребности по каждому входному `Resource`;
- optional cycle time / production rate для будущей симуляции производства;
- состояние активности, если модуль может быть отключен событиями или сценарием.

Минимальное правило для торговли:

- если станция имеет производящий модуль, которому нужен `Resource`, этот `Resource` считается `ConsumedResource` для выбора коэффициента цены;
- если один ресурс нужен нескольким производящим модулям, для выбора категории достаточно факта потребления хотя бы одним модулем;
- числовой коэффициент потребности производящего модуля сохраняется в данных и должен быть доступен будущей производственной системе, но точная формула влияния этого коэффициента на объем расхода/цену требует отдельного балансного решения.

## Формула цены

Каждая продаваемая/покупаемая номенклатура должна иметь `BasePriceCredits`.

Базовые цены ресурсов:

| Resource | Id | Base price |
| --- | --- | ---: |
| `Ice` | `RES-2001` | `10 Credits` |
| `Iron Ore` | `RES-2002` | `5 Credits` |
| `Silicon` | `RES-2003` | `40 Credits` |
| `Magnesium Ore` | `RES-2004` | `30 Credits` |

Базовые цены товаров:

| Good | Id | Base price |
| --- | --- | ---: |
| `Water` | `ITM-3001` | `14 Credits` |
| `Steel` | `ITM-3002` | `40 Credits` |
| `Energy Cells` | `ITM-3003` | `50 Credits` |
| `Fuel` | `ITM-3004` | `10 Credits` |
| `Protein mass` | `ITM-3005` | `110 Credits` |

Итоговая цена в окне торговли:

```text
unitPriceCredits = RoundToCredits(BasePriceCredits * Product(applicable StationPriceFactor))
```

Где:

- `RoundToCredits` округляет до ближайшего целого `Credits`;
- при точной половине используется текущее правило Engine: `MidpointRounding.AwayFromZero`;
- authoritative путь не должен использовать `float`/`double` для денег и коэффициентов; коэффициенты хранятся как fixed-point или рациональные значения;
- порядок перемножения факторов не должен менять результат для одинакового набора входных данных.

Минимальные применимые факторы:

- коэффициент размера станции по категории номенклатуры;
- коэффициенты station events / buffs / debuffs;
- будущие производственные факторы, если они явно введены отдельным решением.

## События, бафы и дебафы станции

Станционное событие должно иметь:

- stable id;
- display name;
- optional description для UI;
- список price factors по категории или конкретному `TradeItem`;
- время действия или флаг постоянного сценарного эффекта;
- deterministic порядок применения при одинаковом времени начала.

События должны сохраняться/загружаться вместе со станцией, если они влияют на текущие цены.

## Схема данных

Требуемые расширения data model:

- `ItemTypeDefinition` получает категорию торговли: `Resource | Good`;
- `ItemTypeDefinition` должен включать category/id/`BasePriceCredits` для всех торгуемых ресурсов и товаров;
- `ModuleTypeDefinition` или отдельный station-service catalog должен включать `BasePriceCredits` для модулей, которые станция продает/покупает;
- `SpaceObjectData` для станции получает `stationSize`;
- станция получает список producing modules или ссылку на station economy profile;
- станция получает список active station events / price modifiers;
- save/load сохраняет resolved `stationSize`, склад, модификаторы и производственные модули.

## Acceptance criteria

- Стартовая станция `SPC-0002` в `Default` и `Docked` сценариях имеет `stationSize = Large`.
- Стартовая станция имеет явный склад из `Food Rations = 500`, `Energy Cells = 350`, `Fuel = 700`, `Ice = 320`, `Iron Ore = 410`, `Silicon = 70`, `Magnesium Ore = 120`.
- Случайная генерация склада не перезаписывает явно заданный склад стартовой станции.
- Каталог ресурсов содержит `Ice/RES-2001/10`, `Iron Ore/RES-2002/5`, `Silicon/RES-2003/40`, `Magnesium Ore/RES-2004/30`.
- Каталог товаров содержит `Water/ITM-3001/14`, `Steel/ITM-3002/40`, `Energy Cells/ITM-3003/50`, `Fuel/ITM-3004/10`, `Protein mass/ITM-3005/110`.
- Цена каждой строки торговли считается как `Round(BasePriceCredits * allApplicableFactors)`.
- Для `Large` станции `Good` получает коэффициент `1.10`, общий `Resource` получает `1.15`, потребляемый `Resource` получает `1.25`.
- UI торговли показывает итоговую цену, а не базовую цену.
- Продажа `Resource` разрешена только кратно `100`.
- Продажа `Good` разрешена только кратно `10`.
- Продажа `Module` разрешена поштучно.
- Engine authoritative валидирует упаковки продажи и не полагается только на UI stepper.
- Save/load сохраняет размер станции и не меняет цены/склад после загрузки при тех же данных.

## Открытые решения

- Нужны базовые цены для `Food Rations` и продаваемых модулей.
- Нужно зафиксировать, является ли `Fuel` торговой единицей kg и применяет ли к нему упаковка `Good = 10 kg` при продаже игроком.
- Нужно уточнить формулу, как коэффициент потребности производящего модуля влияет на фактический расход сырья и/или дополнительный ценовой множитель.
