# Каталог товаров: схема 2 и совместимость сохранений

Дата: 2026-09-18. Реализация тикета 07-08-02; решения тикета 07-08-01 указаны отдельно от открытых вопросов.

## Принятые и сохранённые правила

| Правило | Значение | Основание |
|---|---|---|
| Шаг Buy/Sell | 1 торговая единица | Прямой ответ пользователя 2026-09-18 |

Отправлен вопрос о начальной линейной модели (чувствительность 1, stock factor 0,5–2, Buy ×1,1, Sell ×0,9, минимум 1). Эти числа не включены в действующую конфигурацию и не меняют текущие цены. Динамический расчёт принадлежит тикету 05.

## Версии

- schemaVersion = 2 — форма JSON-файла товаров; схема 1 и файл без schemaVersion поддерживаются через явное преобразование единиц.
- catalogVersion = 1 — текущая поддерживаемая экономическая версия каталога. Схема 2 требует это поле в каждом файле; старые файлы без поля считаются версией 1.
- Settings.json/economy содержит catalogVersion и rulesVersion; они проверяются относительно загруженного каталога и существующей версии экономических правил времени.
- Неизвестная версия отклоняется. Это не механизм горячего обновления: конфигурация сессии неизменяема.
- Следующее изменение каталога, включая добавление Electronics, должно явно решить совместимость сохранений в тикетах 03/12; нельзя просто обновить контрольный legacy-отпечаток на произвольный новый набор.

## Форма файла

```json
{
  "schemaVersion": 2,
  "catalogVersion": 1,
  "itemTypes": [
    {
      "typeId": "item.food-rations",
      "displayName": "Food Rations",
      "unitMassKg": 1,
      "basePriceCredits": 20,
      "tradeCategory": "Good",
      "tradeUnit": "Ration",
      "storageKind": "Cargo",
      "buyQuantityStep": 1,
      "sellQuantityStep": 1
    }
  ]
}
```

| Поле | Семантика |
|---|---|
| typeId | Непустой уникальный доменный ключ; им пользуются cargo, рецепты и склады |
| catalogCode | Необязательный непустой уникальный дополнительный код; не замена typeId |
| displayName | Непустое представление; переименование не меняет идентичность |
| unitMassKg | Целая масса cargo-единицы; строго > 0 для Cargo, ≥ 0 для FuelTank |
| basePriceCredits | Положительная целая цена торговой единицы; null/отсутствие — неторгуемое содержимое |
| tradeCategory | Resource или Good |
| tradeUnit | Kilogram, Piece, Ration или EnergyCell |
| storageKind | Cargo или FuelTank |
| buyQuantityStep / sellQuantityStep | В текущей версии правил строго 1; иной шаг отвергается, пока алгоритмы не поддерживают другое согласованное правило |

Для schemaVersion 2 категория, единица, хранение и оба шага обязательны. Numeric strings вместо enum-имён не принимаются. Cargo с единицей Kilogram обязан иметь массу 1 кг. Ration/EnergyCell допустимы только как Good/Cargo. FuelTank допустим как Good/Kilogram; историческое UnitMassKg не определяет количество топлива в баке.

Стабильные item.food-rations, item.energy-cells и item.fuel проверяются соответственно как Ration, EnergyCell и FuelTank. Неторгуемый товар может оставаться в общем registry, но явная торговая позиция станции обязана иметь цену. Нулевая цена не означает бесплатную торговлю.

## Преобразование старой схемы

- Отсутствующая категория сохраняет прежний fallback Good.
- item.food-rations → Ration; item.energy-cells → EnergyCell; item.fuel → Kilogram/FuelTank.
- Остальные старые позиции с массой 1 кг → Kilogram; остальные → Piece.
- Остальные типы хранения → Cargo; отсутствующие шаги → 1.
- Количество, масса, цена и ID не меняются. Имена не используются для определения семантики.
- Ошибочные заданные значения не заменяются значениями по умолчанию.

Весь каталог проверяется до публикации registry. Дубли ID/кодов между файлами называют обе исходные записи. Ошибки полей содержат путь и контекст. Ссылки обычных и встроенных фабричных рецептов должны разрешаться; неизвестные и неторгуемые позиции явного станционного склада отклоняются до замены работающего мира.

## Save format 7

GameState.catalogCompatibility содержит catalogVersion, rulesVersion и fingerprint. Fingerprint — SHA-256 от UTF-8 JSON экономических полей товаров, отсортированных по ordinal typeId: TypeId, UnitMassKg, BasePriceCredits, Category, TradeUnit, StorageKind, BuyQuantityStep, SellQuantityStep. Порядок полей и числовое представление enum являются частью алгоритма текущей версии.

Имена, CatalogCode и порядок записей не меняют экономический отпечаток. Цена, масса, единица, хранение, категория, шаг или состав каталога меняют его. Это позволяет обнаружить несовместимое редактирование даже без ручного повышения версии.

Новый Save обязан содержать stamp. Несовпадение отклоняется до мутаций мира; исходный файл не перезаписывается. Статические определения и цены не дублируются в Save, сохраняется только идентичность каталога.

Для старых Save без stamp разрешено только точное совпадение текущего каталога с явно зафиксированным Settings.json/economy/legacyCatalogFingerprint. В проекте записан отпечаток исходных 12 позиций, у которых не менялись масса и цена. Старый Save с изменённым ранее пользовательским каталогом не несёт данных для доказательства совместимости: автоматическое восстановление его исторических единиц невозможно; такая миграция требует отдельного источника прежнего каталога.

Legacy fingerprint не следует автоматически пересчитывать при обычной загрузке или изменении контента. Каталог без товаров допускает старый Save без этого поля; ссылки на неизвестные товары всё равно отклоняются. Новые сценарии без saveFormatVersion остаются авторскими сценариями и получают stamp при первом сохранении.

Эта реализация проверяет каталог и текущую rulesVersion; fingerprint рецептов, станционных профилей и будущих параметров динамических цен относится к последующим версиям и тикету 12.
