# Карта: цикл профилирования и оптимизации, 12 сентября 2026

Сценарий `Default_500`: 500 астероидов, корабль игрока и станция — **502 объекта** в снимке мира. Исходная версия: `f593d7b2abb855b5b3bdba45184c1914fb67d4ea`. Изменения относятся к расчётам и отображению; Approach сохраняет текущую скорость, без ускорения и торможения.

## Методика

Локальный стенд `tools/DeepSpaceSaga.Performance` использует реальные загрузчик сценария, SimulationEngine, SnapshotBuffer и полный GameSessionScreen.Render. Release, .NET 8.0.26, Windows 10.0.26200, 8 доступных логических процессоров. Seed = 500, поверхность Skia 1280×720, исходный масштаб камеры.

На каждый режим — 160 прогревочных операций. Затем 600 кадров для паузы, обычного движения и активного Approach к AST-0001; 1000 снимков мира; 100 приёмов команды Approach вместе с последующим снимком. Отклонённая команда считается ошибкой стенда. Отдельный тест предсказывает позиции всех 502 объектов 2000 раз через прежний immutable API.

Клиентские часы шагают по 1/80 секунды, новые снимки приходят раз в секунду. Загрузка сценария, прогрев и подготовка снимка исключены из времени и выделений памяти кадра. Перед и после нагрузки выполнен полный GC; отдельно записаны выделенные байты, удержанная управляемая память, private bytes процесса и количества GC. Профилирование этапов включается только флагом `--stages`; итоговое сравнение сделано без него.

**Это время CPU/raster-отрисовки, а не измерение FPS окна с GPU/VSync.** Оно показывает стоимость одинаковой работы до/после. Один прогон не характеризует все масштабы, видеокарты, скорости симуляции и возможные команды одновременно. Независимые процессы замеров выполнялись последовательно; обычная фоновая нагрузка ОС не изолировалась.

## Найденные причины и реализация

1. **Следы доминировали во времени кадра.** Промежуточный профиль после первых оптимизаций памяти показал 11,87 мс на обновление/рисование следов из 15,16 мс кадра. Отсечение отдельных невидимых отрезков помогло лишь частично. Теперь `ObjectTrailGeometry` уменьшает детализацию в экранных координатах: каждый пропущенный отсчёт находится не дальше 0,25 пикселя от заменяющего отрезка, отличие альфа-канала от исходного цвета не больше 3/255. Повороты проверяются по всем промежуточным точкам; оба конца и граница красного выхлопа сохраняются. В финальном профиле следы занимают 2,32 мс. История и физика не упрощаются.
2. **История следов сдвигала массив при удалении старых точек.** `ObjectTrailBuffer` хранит её в кольцевом буфере. Удаление начала не копирует оставшуюся историю. Сохраняются прежние правила выборки, 10-секундное окно, перенос следа при паузе и корректная очистка исчезнувших объектов. Границы всей истории позволяют отсекать невидимый след; дополнительные проверки отсекают отдельные отрезки. Это учитывает след, проходящий через экран при невидимом текущем объекте.
3. **Для каждой прогнозной точки создавался большой immutable-снимок.** Баллистический прогноз заполняет переиспользуемый список координат без копирования DTO. `ApproachLineCaptureMath.PredictPose` вычисляет геометрию непосредственно из маршрута; та же функция используется полной симуляцией и прогнозом карты. Для действующего Approach прогноз в профиле теперь не выделяет управляемую память после прогрева. Старые снимки и пользовательские IMotionPredictor не мутируются; нестандартные предикторы сохраняют прежний путь вызова.
4. **Создание снимка мира делало промежуточную копию для каждого обычного объекта.** Прямолинейные координаты теперь сразу попадают в итоговый DTO. Маршруты и поворотные состояния используют прежнюю логику. Вычисление альтернатив кривой Approach возвращает маленькие значения вместо временных списков; поиск по кормовой линии использует ограниченные локальные буферы вместо SortedSet и массивов в куче.
5. **Подписи повторно форматировались и измерялись каждый кадр.** Метрики кешируются с проверкой имени и доступного игроку типа; ушедшие из видимости записи очищаются. Списки очистки переиспользуются. На паузе совпадающая визуальная поза использует исходный снимок. Маркеры вне экрана пропускаются с запасом на свечение и выделение.

Сохранены границы архитектуры: Motion содержит общую математику; Engine не зависит от графики; клиент не ссылается на Engine. Самостоятельный измерительный инструмент ссылается на обе стороны для воспроизводимого эксперимента.

## Память на длительном прогоне

`soak.json`: 9600 полных кадров, 120 секунд модельного времени, снимки 1 Гц, контроль после полного GC каждые 10 секунд.

- Все контрольные точки: 501 след, 100 200 точек, суммарная ёмкость 128 256 элементов. После заполнения истории ёмкость не растёт.
- Управляемая память: примерно 5,98–7,05 МБ; на 120-й секунде 5,99 МБ.
- Private bytes процесса: примерно 29,6–36,1 МиБ; на последней точке 34,1 МиБ. Working set: примерно 63–70 МиБ.
- В этом прогоне устойчивого роста удержанной памяти не обнаружено. Это проверка одной длительно живущей карты; многократное создание/закрытие экранов и долгие игровые сессии здесь не измерялись.

Большая оставшаяся статья выделений активного кадра — около 168 КБ на клиентские immutable-предсказания всех объектов; ещё около 35 КБ создают панели. Прежний общий `Predict` по-прежнему возвращает полноценный снимок. Замена этого публичного контракта требует отдельной работы с визуальными поправками и состояниями команд; текущая оптимизация убирает его использование там, где достаточно координат.

## Проверки и визуальный результат

Полный `dotnet test DeepSpaceSaga.sln --no-restore`: **1627 passed, 5 failed**. Новые проверки покрывают кольцевой буфер с оборачиванием/ростом/удалением, границы кривого следа, допустимую погрешность геометрии, цвет выхлопа, прямолинейные координаты и аналитическое движение по дуге. Существующие проверки Approach, паузы/продолжения, маршрутов, меток и движка прошли.

Пять прежних ошибок не связаны с изменениями: ItemCatalogTests и StationEconomyGenerationTests ожидают 10 предметов при фактических 12; три PortraitComposerTests получают null для отсутствующих ресурсов женских портретов.

Сравнены кадры до/после и визуально проверена обычная карта. `visual-comparison.json`: изменилось 0,48–0,59% пикселей; средняя абсолютная ошибка RGB-канала 0,027–0,032 по шкале 0–255. Кадры не идентичны: упрощение следов меняет сглаживание стыков; максимальная локальная разница канала составляет 22–26. Предел 3/255 относится к цвету рисуемого сегмента, а не к итоговому пикселю после сглаживания и наложения.

PNG находятся в `DSS-Images/temp/map-performance`, вне исходного кода проекта. `before.*` — исходные кадры, `after.*` — итоговые.

## Повторение

Из каталога DSS; установленный .NET SDK с поддержкой net8.0 и восстановленные зависимости проекта:

```powershell
dotnet restore tools/DeepSpaceSaga.Performance
dotnet run --project tools/DeepSpaceSaga.Performance -c Release --no-restore -- D:\DeepSpaceSaga\DSS D:\DeepSpaceSaga\DSS\Docs\Engineering\Performance500\repeat.json
```

Дополнительные режимы после двух обязательных путей:

- `--stages` — время и выделения по этапам кадра.
- `--soak` — 9600 кадров с периодическими контрольными точками памяти.
- `--compare before after` — сравнение сохранённых кадров с указанными префиксами, без запуска симуляции.

`stages.json` — промежуточный профиль, выявивший стоимость следов; `segment-culling.json` — проверка одного только дополнительного отсечения; `after-final.json` — профиль окончательного алгоритма с включённой диагностикой. Основные числа таблиц взяты из финального **неинструментированного** `after.json`.
