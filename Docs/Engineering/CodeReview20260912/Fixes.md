# Исправления по результатам ревью

12 сентября 2026. Исправлены десять конкретных дефектов из [исходного ревью](D:/DeepSpaceSaga/DSS/Docs/Engineering/CodeReview20260912/README.md). Изменения находятся в рабочей копии; коммит не создавался.

| Пункт | Изменение |
| --- | --- |
| 1. UI из фонового потока | `WindowThreadContext` возвращает продолжения в оконный Update. `SessionConnectionLoader` освобождает соединения, созданные после закрытия окна или ещё не принятые окном. При загрузке прежняя сессия сохраняется до подготовки новой. |
| 2. Геометрия охраны | `RuntimeMotion.At` учитывает активный Approach; им пользуются симуляция, охрана и диалоговая стыковка. Завершения циклов и дедлайны охраны обрабатываются в порядке игрового времени. |
| 3. Ошибки соединения | Исходное исключение передаётся читателю снимков. `GameSessionHandle.Failure` останавливает клиентское предсказание; окно показывает локализованное сообщение. Неожиданное штатное закрытие потока также считается ошибкой. |
| 4. Точность Save/Load | Скорость и курс сохраняются дробными числами без округления. Формат сохранения повышен до 4. |
| 5. Повторная доставка | Журнал идентификаторов предотвращает повторное исполнение активных, ожидающих и недавних завершённых команд. Для повторного запроса возвращается известный результат. Журнал и ожидающие команды сохраняются вместе с миром. |
| 6. Переполнение торговли | Buy, Sell и Refuel сначала проверяют арифметику и подготавливают новые значения, затем применяют их совместно. При переполнении возвращается `value_overflow`; деньги, груз, топливо и запасы не изменяются. |
| 7. Пропущенные снимки UI | История результатов и событий наполняется при приёме снимков, независимо от рендера. TradeScreen получает результат по CommandId из этой истории. |
| 8. Конкурирующие сохранения | Блокировка охватывает весь цикл от захвата состояния до переименования файла. После ошибки или отмены собственный временный файл удаляется, блокировка освобождается. |
| 9. Согласованные ID | Допустимые варианты регистра ссылок на объекты, типов и состояний модулей приводятся к каноническим значениям до построения runtime. Проверка диалога выполняется до замены текущего мира. Неизвестная будущая версия сохранения отклоняется. |
| 10. Рост очереди снимков | `SnapshotMailbox` хранит один последний снимок мира, объединяя недоставленные результаты и события по идентификаторам. |

## Границы хранения и совместимость

Журнал завершённых команд и клиентская история ограничены 4096 идентификаторами каждый. Активные и ожидающие команды дополнительно защищены от повторной доставки. Дедупликация очень старой завершённой команды после её вытеснения из журнала не гарантируется.

Почтовый ящик допускает до 4096 недоставленных записей каждого вида событий. Превышение заканчивает поток явной ошибкой; бесконечного накопления полных миров или молчаливого удаления недоставленных событий нет. История отображённых клиенту событий является ограниченным недавним журналом.

Прежние целочисленные поля скорости и курса продолжают читаться. Миграция остальных исторических схем не добавлялась. Approach по-прежнему работает без разгона и торможения, с текущей скоростью корабля.
