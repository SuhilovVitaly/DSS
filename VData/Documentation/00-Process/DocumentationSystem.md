# Правила документации

`Documentation` содержит только поддерживаемые Markdown-документы об игре,
её архитектуре, форматах контента, интерфейсе и инструментах разработки.

| Раздел | Содержание |
|---|---|
| 00-Process | Правила работы, архитектура и поддержание документации |
| 01-Requirements | Действующие требования и границы текущей реализации |
| 02-FirstRelease | Механики и экраны |
| 03-Design | Визуальные и композиционные контракты |
| 04-Engineering | Поддерживаемые технические контракты |
| 06-Tooling | Использование действующих инструментов |

Один контракт описывается в одном месте; остальные документы дают краткую
сводку и ссылку. Численные значения content по возможности не копируются:
ссылка на JSON вне Documentation точнее второго расходящегося каталога.
Отделяй реализованное поведение, принятые требования и ещё не завершённые функции.
При изменении контракта обновляй исходный документ и зависимые сводки, убирай
отменённое описание вместо накопления противоречащих «актуализаций».

Эпики, истории, тикеты, планы исполнения и история приёмки находятся только
в `Board`. История удалённых документов сохраняется в Git. В Documentation
не помещают старые планы, дубли Board, review/run-отчёты, счётчики PASS, замеры
отдельных запусков, логи, дампы, архивы, изображения, JSON/TRX, скрипты и
тестовые проекты. Правило относится и к вложенным папкам; допустим только `.md`.
Новые временные результаты — в `D:/DeepSpaceSaga/artifacts/validation/<task>/<run>/`
с уборкой после работы. Тестовый код остаётся в `tests` и `tools`, не в Documentation.

Перед завершением правки проверь факты по текущему коду, существование относительных
ссылок и отсутствие файлов иных форматов. Редактирование описаний не доказывает
успеха тестов, native UI, производительности или игрового баланса.
