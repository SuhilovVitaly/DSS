# Бой V4: правила

Полная спецификация боя: поле, объекты, движение, стрельба, исход. По ней вместе с [Generation.md](Generation.md) — сборкой боя, случайностью и ИИ — и данными `Data/` бой собирается бой в бой. Эталоны для проверки лежат в `Reference/`.

Числа даны ссылками на поля данных: `rules.*` → `Data/rules.json`, `classes.<id>` → `Data/Frames/`, `weapons` / `engines` / `shields` / `armor` → `Data/Modules/*/`. В скобках — текущее значение.

## 1. Поле и геометрия

- Непрерывная плоскость **без краёв**. Координаты x, y — числа double; x направлен вправо, y — вниз.
- Курс 0° — на восток (+x), растёт по часовой стрелке (к +y). Курс — любой угол.
- `norm(a)` — угол в [−180, 180): `a' = fmod(a + 180, 360)`; если `a' < 0`, прибавить 360; затем вычесть 180.
  - Крайний случай не исправлять: из-за округления `a'` вроде −1e-15 после +360 даёт результат +180.
- `bearing(A, B) = deg(atan2(By − Ay, Bx − Ax))`.
- `dist(A, B)` — √((Bx−Ax)² + (By−Ay)²), правильно округлённый (§1.1).
- `vec(a, L) = (cos(rad(a)) · L, sin(rad(a)) · L)`.
- `clamp(v, lo, hi)`: lo, если v < lo; hi, если v > hi; иначе v.

### 1.1. Числа и вычисления (нормативно)

Без этих правил реализация на другом языке разойдётся с эталоном уже в первые ходы.

- **Тип чисел.** Все дробные величины — IEEE-754 double. Целые (корпус, броня, урон, навыки, счётчики) точные.
- **Порядок вычислений.** Каждая формула считается слева направо ровно в той записи, что дана в спецификации, со скобками как написано. Например:
  - `2 · (точность − ref) / 100` — сначала умножение, потом деление;
  - `x + a + b` — `(x + a) + b`.
- **Градусы и радианы.**
  - `rad(a) = a · 0.017453292519943295` (π/180 одной константой double);
  - `deg(r) = r · 57.29577951308232` (180/π).
  - Не писать `a · π / 180`: в ~27% случаев это даёт другой double.
- **`dist`** — правильно округлённый корень суммы квадратов, как `math.hypot` в Python ≥ 3.10. Наивный `sqrt(dx·dx + dy·dy)` и `Math.hypot` в JavaScript расходятся с ним примерно в 17% случаев.
- **Тригонометрия.** `atan2`, `cos`, `sin` — результаты glibc, на практике правильно округлённые.
- **Целые операции.**
  - `floor` от неотрицательного числа = отбрасывание дробной части;
  - деление «шанс = p / 100» — обычное деление double.
- **Выбор и сортировка.**
  - «Минимум» по ключу — первый элемент с минимальным ключом в порядке списка.
  - Сортировки устойчивые, `false < true`.
  - Порядок ключей объектов JSON — порядок в файле. Каталоги из папок (`Frames/`, `Modules/*/`) идут в порядке имён файлов; на исход их порядок не влияет.
- **Округление в текстах.** Журнал и API показывают `round` с банковским округлением (половина — к чётному). На ход боя это не влияет.

## 2. Объекты

Бой собирается из сценария `scenarios.<id>` (Generation §2): стороны A и B, у каждой носитель и сколько угодно дронов. Порядок объектов везде один:
- дроны: сначала все дроны A по списку сценария, затем все дроны B;
- носители: A, затем B.

**Носитель** (`scenarios.<id>.sides[].carrier`, компоновка рамы `carrier`):
- стоит неподвижно в `x`, `y` с курсом `course`;
- корпус `classes.carrier.hull` (400): `hull` компоновки у носителя не читается;
- броня — пул `armor.<layout.armor>.armor` (`armor.none`, 0);
- манёвренность `classes.carrier.maneuver` (35): пилота нет, это его «защита» в формуле шанса;
- оружия, двигателей, щитов, ПТО и ангара нет;
- может быть целью пушек;
- живой, пока корпус > 0.

**Дрон** — рама, пушка, плиты, щиты и двигатели из компоновки `layouts.<id>` (Data/README.md); пилот из `pilots`.

| Поле | Откуда |
|---|---|
| корпус (максимум и текущий) | `layouts.<id>.hull`, если задан, иначе `classes.<class>.hull`: тяжёлый 65, лёгкий 55; таги 40 (обрез), 45 (самопал), 50 (вожак со щитом) |
| броня (пул, максимум и текущая) | `armor.<plate>.armor`: нет 0, обшивка из хлама 20, латаные 35, лёгкие 50, средние 80, тяжёлые 130 |
| пушка | `weapons.<id>` |
| щиты | `shields.<shield>`, число `n = shieldCount` (по умолчанию 1, если `shield` задан; 0, если `shield` = null). Защита щитов = `defense × n`, масса = `massKg × n`. Слотов `classes.<class>.shieldSlots` (по умолчанию 1): тяжёлый 2, лёгкий 1, таг 1. Щит — маневровые двигатели: −10 к шансу попадания по дрону и всего 10 кг |
| двигатели | `engines.<id>` по списку компоновки, у каждого множитель мощности 1.0; после повреждения `rules.systems.engineDamagedFactor` (0.5) |
| точность, манёвренность | `pilots.<id>.accuracy`, `.maneuver`, целые. Число — у именного пилота; `[min, max]` — у NPC, бросается в каждом бою (Generation §2) |
| позиция, курс, скорость | из сценария, с разбросом расстановки (Generation §2) |
| состояние | `air` (в бою), `disabled` (выведен из строя, §6.4) или `destroyed` (сбит) |
| `jammed` | пушка заклинила до конца боя |
| поворот прошлого движения | \|dc\| последнего хода, градусы |

«В бою» — значит в состоянии `air`. Выведенный из строя и сбитый дроны в бою не участвуют: не планируют, не движутся, не стреляют и не служат целью.

Масштаб чисел — как в Battle Brothers: урон, корпус и броня — целые десятки (урон 30–75, корпус 40–65, броня 20–130).

## 3. Лимиты движения (формула V2)

Считаются заново при каждом обращении, по текущим множителям двигателей:

1. масса = `frameMassKg` рамы + масса плит + масса пушки + масса щитов (`massKg × n`) + Σ масс двигателей — сложение в этом порядке;
2. `k = referenceMassKg / масса`;
3. `vmin = minSpeed`;
4. `vmax = min(maxSpeedCap, vmin + Σ(speedBonus × множитель) × k)`;
5. `change = Σ(speedChange × множитель) × k`;
6. `turn = min(turnCapDeg, Σ(turnDeg × множитель) × k)`.

Суммы Σ начинаются с 0 и идут по двигателям в порядке списка; к k умножается уже вся сумма.

- **Скорость на ход:** `clamp_speed(v) = clamp(clamp(v, текущая − change, текущая + change), vmin, vmax)`. Через неё проходит любая скорость приказа.
- **Предел поворота при скорости v:** `turn × (1 − (1 − f) × clamp((v − vmin) / (vmax − vmin), 0, 1))`, где f = `rules.turnAtMaxSpeedFraction` (0.5). Если vmax ≤ vmin, предел равен `turn`.
- **Стартовая скорость** из сценария сразу ограничивается: `clamp(v, vmin, vmax)`, при создании дрона, до бросков навыков и разброса.
- **Повреждение двигателя** текущую скорость не меняет. Новые лимиты действуют с ближайшего приказа.

Пример: тяжёлый с мечом I, средними плитами, двумя щитами I и 2 стандартными двигателями (масса от корпуса не зависит).
- Масса 460 + 120 + 70 + 2 × 10 + 200 = 870, k ≈ 0.874.
- vmax ≈ 93.7, change ≈ 17.5, поворот ≈ 56.8°.
- На vmax поворот ≈ 28.4°.

Таг с самопалом I, латаными плитами и одним лёгким маршевым:
- масса 260 + 30 + 50 + 70 = 410, k ≈ 1.854;
- vmax ≈ 82.1, change ≈ 16.7, поворот ≈ 55.6°.

## 4. Ход

Ход номер N (с 1):
1. **Планирование:** приказ (скорость v, поворот dc) каждому дрону в бою (Generation §3). Никто не движется, все приказы видят одно и то же положение.
2. **Движение** (§5).
3. **Проверка исхода** (§7). В чистом движке она не может сработать, потому что движение не меняет корпус, но порядок такой.
4. **Стрельба:** один одновременный залп (§6).
5. **Проверка исхода.**

Фазы пуска нет: торпед, ангара и взлёта нет. Все дроны в бою с первого хода.

## 5. Движение

Каждый дрон в бою по своему приказу (v, dc) проходит путь из n = `rules.substeps` (4) подшагов. Для i = 1…n:
1. `курс = курс + dc / n`;
2. `(dx, dy) = vec(курс, v / n)`; `x = x + dx`; `y = y + dy`.

Между подшагами курс не нормализуется. После последнего подшага `курс = norm(курс)`. Скорость дрона становится v, «поворот прошлого движения» — |dc|.

- Дроны движутся по очереди в порядке списка, но друг на друга не влияют.
- Выведенные из строя и сбитые стоят на месте.
- Столкновений нет: дроны проходят сквозь друг друга и носители.
- Краёв нет.

## 6. Стрельба

### 6.1. Цели

Кандидаты дрона — враги, которые одновременно:
- вражеский дрон в бою или живой вражеский носитель;
- `dist(дрон, цель) ≤ range` пушки;
- `|norm(bearing(дрон, цель) − курс дрона)| ≤ arcDeg`.

У дрона с заклинившей пушкой и у дрона не в бою кандидатов нет. Порядок кандидатов: вражеские дроны в порядке списка, затем вражеский носитель. Для каждого кандидата запоминаются расстояние и угол `norm(bearing(дрон, цель) − курс)`.

Каждый дрон стреляет **один раз за ход** в одну цель или не стреляет. Выбор цели ИИ — Generation §3.8.

### 6.2. Шанс попадания (в стиле Battle Brothers)

Слагаемые в процентных пунктах. Сумма начинается с 0 и идёт в этом порядке:

```
p = 0
p += точность стрелка
p += −манёвренность цели
p += hit.base (50)
p += hitBonus пушки
p += rangeBonus × max(0, 1 − расстояние / range)         — близость: rangeBonus пушки, иначе hit.rangeBonus (15)
p += −((|угол| / arcDeg) × hit.anglePenalty (12))         — угол к кромке сектора
если цель — дрон и |norm(bearing(цель, стрелок) − (курс цели + 180))| ≤ hit.rearBonusArcDeg (30):
    p += hit.rearBonus (10)                               — заход в хвост
если цель — дрон, у неё задан щит и выстрел не в корму (§6.3):
    p += −(defense × n)                                   — щиты (при n = 0 слагаемое 0)
шанс = clamp(p, hit.minChance (5), hit.maxChance (95)) / 100
```

Манёвренность носителя — `classes.carrier.maneuver`. Хвоста и щита у носителя нет.

Пример. Марта (точность 59) с мечом I (+0) бьёт в лоб тага (манёвренность 47) со щитом с 50 единиц, цель точно по носу: 59 − 47 + 50 + 0 + 9 − 0 − 10 = 61%. Тот же выстрел в корму: 59 − 47 + 50 + 9 + 10 = 81%, щит не действует. На пределе дальности бонуса нет: 52% и 72%.

### 6.3. Корма

- Выстрел **в корму** — если цель дрон и `|norm(bearing(цель, стрелок) − (курс цели + 180))| ≤ rear.arcHalfDeg` (45).
- Это отдельная, более широкая дуга, чем ±30° бонуса за хвост.
- Носитель кормы не имеет.
- В корму не действуют ни броня, ни щит. Шанс мгновенной гибели — `rearKillChance` пушки; у оружия тагов он 0.

**Сектор:** `arcDeg` — полусектор, ± от носа. Полный угол — 2 × `arcDeg` (у копья I 90°); интерфейс показывает полный угол.

### 6.4. Залп — одновременный

Цели, расстояния, углы, шансы и признак «в корму» берутся по снимку после движения, до любого выстрела. Стреляют все выбранные стрелки, в том числе те, кого собьют в этом же залпе. Порядок стрелков задаёт только порядок бросков.

1. **Выстрелы.** Стрелки — дроны в бою в порядке списка (A, затем B), у которых выбрана цель. Для каждого выстрела по порядку:
   1. `u = random()`: попадание при `u < шанс` (шанс — уже делённое на 100 число из §6.2);
   2. при промахе выстрел закончен: 1 бросок;
   3. при попадании — урон `D = randint(damageMin, damageMax) = damageMin + floor(random() × (damageMax − damageMin + 1))`;
   4. если выстрел в корму — ещё бросок `u3 = random()`, гибель при `u3 < rearKillChance`. Бросок тратится при любом попадании в корму, даже при `rearKillChance` = 0;
   5. **потеря «в одиночку»** — для проверки систем: D для кормы; иначе потеря корпуса этого одного попадания против брони цели **до залпа** (пункт 2).

   Итого бросков на выстрел: промах — 1, попадание не в корму — 2, попадание в корму — 3.
2. **Урон по каждой цели.** Цели — в порядке первого попадания по ним. Для цели `корпус = броня = 0` (потери), по её попаданиям в порядке выстрелов:
   - попадание в корму: `корпус += D`, броня не участвует;
   - иначе `(потеря, поглощено) = split(D, piercing пушки стрелка, текущая броня цели − броня)`; `корпус += потеря`; `броня += поглощено`.

   `split(D, piercing, A)`:
   - `прямо = min(D, piercing)`;
   - `остаток = D − прямо`;
   - `поглощено = min(max(A, 0), остаток)`;
   - `потеря = прямо + остаток − поглощено`.

   Затем:
   - если хотя бы одно попадание дало гибель в корму, `корпус = текущий корпус цели`;
   - `корпус = min(корпус, текущий корпус цели)`; корпус цели −= корпус, броня цели −= броня. Избыточный урон пропадает.
3. **Состояния** — по всем дронам в порядке списка:
   - дрон в бою с корпусом ≤ 0 → `destroyed`;
   - иначе дрон в бою с корпусом ≤ `floor(rules.disabled.hullFraction × максимум корпуса)` → `disabled`, его скорость = 0. При 0.3 это тяжёлый ≤ 19, лёгкий ≤ 16, таги ≤ 12 / 13 / 15.
     - Выведенный дрон стоит на месте, не стреляет, не планирует, не цель и не враг: ИИ его не видит, повреждений систем он не получает.
     - Для исхода (§7) и потерь в сериях он выбыл, как сбитый.
     - В этом залпе он ещё стрелял: залп одновременный.
   - Носитель с корпусом ≤ 0 уничтожен. Носитель из строя не выводится.
4. **Повреждение систем.** Идёт после состояний, по попаданиям в порядке выстрелов. Каждое подходящее попадание бросает отдельно, так что один дрон может бросать несколько раз. Попадание подходит, если цель — дрон, всё ещё в бою, и его потеря «в одиночку» ≥ `rules.systems.minHullLoss` (40):
   1. эффект = `weighted(rules.systems.table)`: «заклинило пушку» или «двигатель», веса 1 : 1;
   2. `weaponJammed`: если пушка цела — `jammed = true`, иначе ничего;
   3. любой другой эффект — двигатель:
      - целые двигатели — с множителем ровно 1.0, в порядке списка;
      - если они есть, `choice(целые)`, и множитель выбранного становится `engineDamagedFactor` (0.5);
      - если целых нет — ничего, броска нет.

## 7. Исход

Сторона проигрывает, если:
- её носитель уничтожен (корпус ≤ 0) — причина ««<носитель>» уничтожен», или
- у неё нет ни одного дрона в бою (все сбиты или выведены из строя) — «у «<носитель>» не осталось дронов».

Носитель проверяется первым. Проверка идёт после движения и после залпа:
- проиграла одна сторона — победа другой, исход `A` или `B`;
- проиграли обе в одной проверке — ничья `draw`, причины через «; » (сначала A).

Лимита ходов в игре нет. В автоматических сериях бой идёт, пока нет исхода и номер хода < `rules.seriesTurnCap` (100). Если исхода нет и после хода 100, исход `timeout`, ходов 100.

**Потери стороны** в итоге боя — число её дронов не в бою (`destroyed` + `disabled`).

### 7.1. Статистика боя

Счётчики для отчётов. На ход боя они не влияют:
- `shots`, `hits`, `rearHits`, `rearKills` — за весь бой;
- `systems` — число бросков систем, в том числе ничего не изменивших;
- `disabled` — сколько раз дрон стал `disabled`;
- `hull`, `armor` — суммы снятого корпуса (после обрезки по корпусу цели) и брони;
- `carrierHull` — то же по носителям;
- `firstLoss` — сторона первого объекта, выбывшего в залпе (дроны по списку, затем носители);
- по каждой пушке: `shots`, `hits`, `rearHits`, `rearKills`, `hull`. `hull` += min(потеря «в одиночку», снято с цели) или всё снятое при гибели в корму; одно снятие может засчитаться нескольким пушкам.

Эталоны в `Reference/` используют: исход, причину, ходы, потери, корпус носителей, `shots`, `hits`, `rearHits`, `systems`, `disabled`.

## 8. Ориентиры баланса

Числа данных подобраны под эти ориентиры. Проверка — Generation §4 и `Reference/series.md`.

- **Броня, как в Battle Brothers**, снимается раньше корпуса. Броню тага (20–50) оружие игрока снимает за 1, максимум 1.5 обычного попадания. Броню дрона игрока (80) оружие тагов снимает за 2–2.5 попадания.

  Среднее число обычных попаданий до нуля брони (точный расчёт по распределению урона):

  | Пушка → броня | 20 | 35 | 50 | 80 |
  |---|---|---|---|---|
  | Меч I 50–75 | 1.00 | 1.00 | 1.00 | |
  | Копьё I 40–60 | 1.00 | 1.00 | 1.48 | |
  | Самопал I 30–60 | | | | 2.22 |
  | Обрез I 40–50 | | | | 2.00 |

- **Корпус после брони.** Корпус у игрока и тагов схожий: 55–65 и 40–50. Без брони дрон выходит из боя с 1, редко с 2 обычных попаданий. Если попадание его не сбило, корпуса остаётся ≤ 30%, и дрон выведен из строя.

  Доля дронов, вышедших из боя не позже первого попадания после того, на котором кончилась броня:

  | Пушка → цель | Таг 40+20 | Таг 45+35 | Таг 50+50 | Тяжёлый 65+80 | Лёгкий 55+80 |
  |---|---|---|---|---|---|
