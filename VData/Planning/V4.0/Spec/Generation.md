# Бой V4: сборка, случайность, ИИ, серии

Здесь описано:
- как из данных появляется бой;
- откуда берутся случайные числа и в каком порядке они тратятся;
- как ходит и выбирает цели ИИ;
- как считаются серии.

Механика — в [Combat.md](Combat.md). Нормативные правила вычислений (double, порядок операций, `rad`/`deg`, `dist`) — Combat §1.1, они действуют и здесь.

## 1. Случайные числа

Один поток **mulberry32** на бой от `seed`: состояние `x = seed mod 2^32`, беззнаковое 32-битное. Вызов `random()`:

```
x = (x + 0x6D2B79F5) & 0xFFFFFFFF;  t = x
t = ((t ^ (t >>> 15)) * (t | 1)) & 0xFFFFFFFF
t = t ^ ((t + (((t ^ (t >>> 7)) * (t | 61)) & 0xFFFFFFFF)) & 0xFFFFFFFF)
return ((t ^ (t >>> 14)) & 0xFFFFFFFF) / 4294967296
```

- Умножение — в 64-битных беззнаковых или `Math.imul`, затем маска `& 0xFFFFFFFF`.
- `>>>` — логический сдвиг.
- Результат — double в [0, 1).
- Контроль: seed 1 → 0.6270739405881613, 0.002735721180215478, 0.5274470399599522; seed 4294967295 → 0.8964226141106337. Бит в бит совпадает с генератором V3.

Производные:
- `uniform(lo, hi) = lo + (hi − lo) · random()`;
- `randint(lo, hi) = lo + floor(random() · (hi − lo + 1))`;
- `choice(список) = список[floor(random() · n)]`;
- `weighted(таблица)`: `r = random() · Σвес`; по строкам по порядку `r = r − вес`, берётся первая строка с `r < 0`. Если такой нет, берётся последняя.

**Все вызовы `random()` в бою, по порядку:**

1. **Сборка** (§2):
   1. навыки NPC — по дронам в порядке списка: сначала точность, затем манёвренность, только для значений `[min, max]`;
   2. разброс — по дронам в порядке списка, 3 вызова на дрон: x, y, курс.
2. **Каждый ход:**
   1. планирование — по дронам в бою в порядке списка; внутри дрона сначала манёвр роли, затем «выход в хвост» (§3.1):
      - `pursue` — 2 вызова (x, затем y). Вызывается только в ветках: погоня истребителя, перехватчик «враг у носителя», перехватчик «атака угрозы»;
      - заход и отход ударника, заслон и патруль перехватчика, выход из виража истребителя — 0 вызовов;
      - «выход в хвост» — 1 вызов, только если дрон не заклинило и подходящий приказ нашёлся;
   2. залп — по выстрелам (Combat §6.4): промах 1, попадание 2, попадание в корму 3;
   3. системы — по подходящим попаданиям (Combat §6.4 п. 4): 1 вызов `weighted` и ещё 1 `choice`, только если эффект — двигатель и есть целый двигатель.

`Reference/battles.md` даёт число вызовов на бой, `Reference/trace-seed-1.md` — после каждого этапа одного боя.

## 2. Сборка боя из данных

- **Данные** — папка `Data/` (Data/README.md): корневые файлы, `Frames/`, `Modules/*/`. Загрузка проверяет ссылки и типы; любая ошибка останавливает запуск с указанием файла и поля:
  - урон, корпус, броня, `piercing`, `defense`, `hitBonus`, навыки — целые;
  - `damageMin ≤ damageMax`, `0 < arcDeg ≤ 180`, `range > 0`;
  - ссылки компоновок существуют;
  - у носителя нет пушки и двигателей; у дрона 1…`engineSlots` двигателей и не больше `shieldSlots` щитов;
  - у сценария стороны A, B по порядку, тактики существуют, id дронов не повторяются;
  - у фиксированной тактики целые `striker`/`interceptor`/`fighter`.
- **Сценарий** — `scenarios.<id>`, по умолчанию первый в файле. Поля: `name`, `description`, `goal` (§4) и `sides` — ровно A и B. У стороны: `tactic`, `carrier`, `drones[]` — любое число дронов.
- **Порядок объектов:** дроны A по `sides[0].drones`, затем дроны B; носители A, B (Combat §2).
- **Переопределение компоновки** — по id дрона, перед боем. Это поверхностная замена полей компоновки (`weapon`, `armor`, `shield`, `shieldCount`, `hull`, `engines` — какие переданы), без повторной проверки слотов.
  - Страница боя игрока передаёт только `weapon`, `armor`, `shield` (пустая строка = null) и `shieldCount`:
    - `shieldCount` = переданное целое или 1, если щит задан;
    - 0 без щита.
  - Если в переопределении есть `shield`, но нет `shieldCount`, число остаётся от исходной компоновки.
- **Дрон при создании:**
  - id, позиция, курс и скорость из сценария;
  - корпус и броня полные, пушка цела, двигатели ×1.0;
  - роль «истребитель», `role_since = 0`, режим ударника «на заход»;
  - `hunt` нет, `dry = 0`, `extend = 0`;
  - стартовая скорость ограничивается `clamp(v, vmin, vmax)` (Combat §3).
- **Навыки NPC.** Для каждого дрона по порядку списка: если `pilots.<id>.accuracy` — пара `[min, max]`, то `точность = randint(min, max)`; затем так же манёвренность. Именные пилоты (число) бросков не тратят.
- **Разброс расстановки** — для каждого дрона по порядку списка:
  - `x = x + uniform(−s, s)`, затем `y = y + uniform(−s, s)`, где s = `rules.deployScatter.xy` (12);
  - `курс = norm(курс + uniform(−c, c))`, где c = `deployScatter.courseDeg` (6).

  Носители не смещаются.
- **Середина** — `((xA + xB) / 2, (yA + yB) / 2)` носителей, нужна для привязи (§3.2).
- **Тактика стороны** — `sides[].tactic` сценария, если её не переопределили перед боем.
- **Начальные роли** (сторона A, затем B):
  1. раскладка тактики `ai.tactics.<id>`. Для «командира» (`adaptive`) берётся раскладка тактики `ai.commander.startTactic` (`balanced`);
  2. список слотов: `striker` × n, `interceptor` × n, `fighter` × n по раскладке;
  3. дроны стороны сортируются устойчиво по максимуму корпуса по убыванию и по порядку получают слоты; дроны сверх слотов — истребители;
  4. `role_since` остаётся 0, поэтому командир не может сменить роль раньше хода 3 (`ход − role_since ≥ minRoleTurns`), и ходы 1–2 идут по раскладке `startTactic`.

Состав сценария `initial` («Начальный бой») с координатами — в Data/README.md: 4 дрона игрока против 6 тагов.

## 3. ИИ: планирование хода

### 3.1. Порядок

Для стороны A, затем B:
1. если тактика стороны — «командир», распределение ролей (§3.6);
2. если у стороны есть дроны в бою и **все** они перехватчики, каждый становится истребителем (`role_since = ход`, без проверки `minRoleTurns`), запись «X: теперь истребитель (атаковать больше некому).». Так две стороны, охраняющие свои носители, не застревают навсегда. Действует при любой тактике.

Затем приказ каждому дрону в бою по порядку списка:
1. **Действующая роль** = роль дрона; но если она «истребитель» или «перехватчик» и у врага нет дронов в бою — «ударник».
2. Приказ действующей роли (§3.3–3.5).
3. Если действующая роль не «ударник» или `ai.striker.takesTail` = true — «выход в хвост» (§3.7). Если он вернул приказ, тот заменяет приказ роли.

### 3.2. Руление к точке и погоня

**`steer(d, P, v)`:**
1. Привязь: если `dist(d, середина) > ai.leash.radius` (420), P = середина. Меняется только точка; переданная скорость v не пересчитывается.
2. `err = norm(bearing(d, P) − курс d)`; `v = clamp_speed(v)`; `limit = предел поворота(v)`.
3. Если `ai.pursuit.slowForTurn` и `limit < |err|`:
   - `L = clamp_speed(текущая скорость − change)`, `n = ai.pursuit.slowForTurnSteps` (4);
   - для k = 1…n: `v = v + (L − v) · k / n` (v — значение с прошлого шага), `limit = предел поворота(v)`;
   - стоп, как только `limit ≥ |err|`.
4. Приказ: `(v, clamp(err, −limit, limit))`.

Любая целевая скорость (vmax, vmin, `attackSpeed`, `patrolSpeed`, скорость погони) проходит через `clamp_speed`, то есть ограничена изменением за ход. Приказы «выхода из виража» и «выхода в хвост» `steer` не вызывают, привязь на них не действует.

**Прогноз врага** `predict(e)`: прямо по курсу с текущей скоростью от положения в начале хода: `(x, y) + vec(курс, скорость)`, курс тот же.

**`pursue(d, e)`:**
1. `(px, py, pc) = predict(e)`; `(tx, ty) = vec(pc, −tailOffset)` (35).
2. `r = (1 − 2 · (точность d − aimAccuracyRef) / 100) · aimErrorScale`, где aimAccuracyRef = 50, aimErrorScale = 14.
3. `px = px + tx + uniform(−r, r)`, затем `py = py + ty + uniform(−r, r)`.
4. `v = speedFactor (1.15) · dist(d, (px, py))`.
5. `steer(d, (px, py), v)`.

### 3.3. Ударник

Заходы на вражеский носитель C. Режим дрона «на заход» или «отход», в начале — «на заход»:
1. На заходе, если `dist(d, C) < breakDistance` (40), — переключиться на отход.
2. Иначе, на отходе, если `dist ≥ extendDistance` (140), — переключиться на заход.
3. Заход: `steer(d, C, attackSpeed)` (50 — медленно, чтобы носитель дольше оставался в секторе).
4. Отход: `steer` в точку `C + vec(bearing(C, d), extendDistance + breakDistance)` со скоростью vmax.

### 3.4. Перехватчик

**Угрозы стороны** `threats(side)`, общие с командиром §3.6 — вражеские дроны в бою, для которых, при `D = dist(e, свой носитель)`:
- `D ≤ commander.threatRadius` (250), или
- выполнены оба условия:
  - враг летит на носитель: `|norm(bearing(e, носитель) − курс e)| ≤ threatHeadingDeg` (60°);
  - и успеет долететь: `D ≤ threatTurns (5) · vmax(e)`.

Берётся максимальная скорость, а не текущая: ударник заходит медленно (`attackSpeed` 50), и по текущей скорости угрозу заметили бы слишком поздно. Порядок угроз — по D, при равенстве — по порядку списка.

Перехватчик d выбирает действие так:
1. Если есть враги-дроны в бою с `dist(e, свой носитель) ≤ patrolRadius` (120) — `pursue` за ближайшим к носителю (при равенстве — первым по списку).
2. Иначе, если угрозы есть, — **заслон** против первой угрозы e:
   1. если `dist(d, e) ≤ range пушки × engageFactor` (1.0) — `pursue(d, e)`;
   2. иначе:
      - `b = bearing(носитель, e)`;
      - номер i = позиция d среди дронов своей стороны в бою с ролью «перехватчик», в порядке списка, с 0;
      - знак `σ = +1` при чётном i, `−1` при нечётном;
      - точка `S = (носитель.x + sx + fx, носитель.y + sy + fy)`, где `(sx, sy) = vec(b, screenDistance)` (90) и `(fx, fy) = vec(b + 90·σ, flankOffset)` (0, сдвиг выключен);
   3. если `dist(d, S) ≤ screenHold` (40) — `steer(d, (e.x, e.y), vmin)`: носом к текущему положению угрозы, медленно;
   4. иначе — `steer(d, S, vmax)`.
3. Иначе патруль:
   - `шаг = min(patrolOrbitStepDeg (70), orbitTurnFraction (0.8) · предел поворота при patrolSpeed)`;
   - точка `носитель + vec(bearing(носитель, d) + шаг, patrolOrbitRadius (70))`;
   - `steer(d, точка, patrolSpeed (65))`.

   Шаг ограничен, чтобы орбита не просила поворота больше, чем дрон может сделать.

### 3.5. Истребитель

1. Если `extend > 0`: `extend = extend − 1`, приказ `(clamp_speed(vmax), 0)`.
2. Иначе, если `dry ≥ breakAfterTurns` (3):
   - `dry = 0`, `extend = extendTurns − 1` (0);
   - запись «X выходит из виража на новый заход.»;
   - приказ `(clamp_speed(vmax), 0)`.
3. Иначе погоня `pursue` за целью `hunt`, если она ещё в бою. Иначе новая цель — ближайший враг-дрон в бою (при равенстве — первый по списку), она запоминается в `hunt`. `hunt` сохраняется и при смене роли.

После любого из этих приказов §3.1 ещё пробует «выход в хвост», и он может заменить прямой выход из виража.

`dry` обновляется в начале каждой стрельбы для всех дронов в бою: 0, если у дрона есть кандидаты (Combat §6.1), иначе +1.

### 3.6. Командир

Каждый ход, для стороны с тактикой «командир», если у неё есть дроны в бою:
1. **Угрозы** — `threats(side)` (§3.4), их число T.
2. **Перехватчиков:** 0, если T = 0; иначе `min(maxInterceptors (4), T + extraInterceptors (1), свои дроны в бою)`. Остаток `rest`.
3. **Ударников:**
   - если у врага нет дронов в бою — все `rest`;
   - иначе `min(rest, max(0, свои − вражеские))`;
   - если получилось 0, у врага есть дроны, `rest > 0` и корпус вражеского носителя `<` `strikeWhenEnemyCarrierBelow (0.5) × максимум` — один.
4. **Распределение.** Свободные — все свои дроны в бою, в порядке списка.
   - Сначала перехватчики, потом ударники.
   - Каждый раз берётся первый свободный с минимальным ключом `(не в этой роли сейчас, dist до опоры)`. Опора перехватчика — свой носитель, ударника — вражеский.
   - Остальные получают план «истребитель».
5. **Смена роли:** для каждого своего дрона в бою по порядку, если план ≠ текущая роль и `ход − role_since ≥ minRoleTurns` (3) — роль = план, `role_since = ход`, запись «X: теперь <роль>.».

   Заблокированные смены не выполняются, поэтому фактическое число ролей может отличаться от плана.

### 3.7. Выход в хвост

Не выполняется у дрона с заклинившей пушкой: возвращает «ничего», броска нет.

1. **Сетка приказов:**
   - скорости: `clamp_speed(текущая + change · k / ns)` для k = −ns…ns, где ns = `ai.tail.speedSteps` (2), то есть 5 скоростей; повторы (точное равенство double) убираются, по возрастанию;
   - для каждой скорости v — повороты `dc = предел(v) · k / nt`, k = −nt…nt, где nt = `ai.tail.turnSteps` (6), то есть 13 поворотов.
2. **Подбор.** `reach = range пушки × rangeFactor (0.8)`, `cone = arcDeg × coneFactor (0.8)`. Для каждого врага-дрона в бою по порядку списка:
   - пропустить, если `dist(d, e) > (vmax + reach) + скорость e`;
   - `(ex, ey, ec) = predict(e)`;
   - для каждого (v, dc) по порядку: `(x, y, c) = конец пути` из d по (v, dc), по Combat §5, с нормализованным курсом. Конец подходит, если одновременно:
     - `dist((x, y), (ex, ey)) ≤ reach`;
     - `|norm(bearing((ex, ey), (x, y)) − (ec + 180))| ≤ rules.rear.arcHalfDeg` (45) — конец в кормовой дуге прогноза;
     - `|norm(bearing((x, y), (ex, ey)) − c)| ≤ cone` — прогноз в конусе пушки.
   - Оценка = `dist / reach`.
3. **Лучший** — с минимальной оценкой, строго меньше предыдущей лучшей, поэтому при равенстве остаётся первый в порядке врагов, скоростей, поворотов.
4. Если лучший нашёлся — один бросок: при `random() < chance` (0.85) приказ = (v, dc) лучшего; иначе «ничего». Если не нашёлся — броска нет.

### 3.8. Цель в залпе

Кандидаты (Combat §6.1) сортируются устойчиво по ключу `(группа, расстояние)`:
- у дрона с ролью «ударник» (роль самого дрона, не действующая роль) носитель идёт в группе 0, дроны — в группе 1;
- у остальных наоборот.

Берётся первый кандидат. Пустой список — не стрелять. В бою игрока это подсказка по умолчанию.

## 4. Серии, цель сценария и эталон

- **Серия** — бои сценария для seed `from…to`. Сторона A — заданной тактикой, B — своей из сценария. Предел — `rules.seriesTurnCap` (100) ходов.
- **Цель сценария** — `goal` (значения в Data/README.md):
  - `playerSide` — сторона игрока (A): ею командует игрок в бою игрока, по ней считается цель;
  - `winMaxOneLoss` — доля боёв, где сторона `playerSide` победила, потеряв не больше одного дрона (0.80);
  - `winNoLoss` — доля побед без потерь (0.60);
  - `tolerance` — допуск (0.03).

  - `seeds` — `[первый, последний]` сид замера (1…1000).

  Замер: сторона `playerSide` играет своей тактикой из сценария, другая — своей, сиды `seeds`. «Потеря» — дрон, вышедший из боя: `destroyed` или `disabled`. «В цели», если обе доли отличаются от целевых не больше чем на допуск. Без `goal` — сторона A и сиды 1…1000.
- **Отчёты** `tools/DeepSpaceSaga.CarrierWingSim/scripts/wing4_series.py`:
  - `--goal [--scenario id]` — каждая тактика A против стороны B, первая строка — тактика по умолчанию, и вердикт;
  - `--hits` — точное среднее число обычных попаданий до выхода из боя;
  - матрица тактик и `--guns` — сравнения.
- **Эталон текущей редакции** — `Reference/`:
  - `series.md` — замер цели;
  - `battles.md` — 90 боёв: исход, ходы, потери, счётчики, число бросков;
  - `trace-seed-1.md` — полный ход одного боя.

  Реализация по этой спецификации должна воспроизвести их бой в бой (`scripts/v4_reference.py --check`).
