## Verified findings

1. **P1 — Rearm UI is not wired.** `ShipScreen.cs:37-51` handles only close; `ShipRearmController`
   (`ShipWingPanel.cs:35`) is test-only; no `RearmDroneAsync` call exists from the screen.
   Owning ticket: US-0009 TK-0003.
2. **P1 — Disabled and engine damage are lost between battles.** `SimulationEngine.SortieSettlement.cs:42-49`
   copies hull/armor/ammo/jam/decoy only; `TacticalDroneStatus.Disabled` and
   `TacticalEngineState.Factor` have no persisted fields in `OwnedDroneData`. Next sortie restores
   intact engines/Air. Owning ticket: US-0006 TK-0002 (persistence) + US-0005 TK-0002 (restore).
3. **P1 — A sortie launches from an unready hangar.** `SimulationEngine.TacticalBattle.cs:103`
   filters only `Destroyed`; `IsHangarReady` and disabled status are not checked. Owning ticket:
   US-0005 TK-0003.
4. **P1 — Owned pilot comes from the encounter slot, not the persistent crew.** `OwnedBattleAssembly.cs:115-131`
   uses `start.Pilot` and a shifting `slotIndex`; a destroyed early drone shifts survivors onto
   another pilot's alias. `TacticalBuildSnapshot.PilotGender/PilotPortraitAssetId/PilotRole` exist
   but are never populated. Owning tickets: US-0005 TK-0002 (engine), US-0010 TK-0001 (client
   identity), US-0011 TK-0001/TK-0002 (skill scale + manifest values).
5. **P1 — Wing validation accepts bad equipment references.** `OwnedWingValidator`
   (`SimulationEngine.OwnedWing.cs:105-151`) checks numeric bounds only; unknown layout/weapon/
   engine/shield/decoy and over-capacity magazines/slots pass. Owning ticket: US-0003 TK-0002.
6. **P2 — Carrier appearance is not used by the tactical renderer.** `TacticalShipSprites.cs:43`
   always selects `"carrier"`; `CarrierAppearance` has no production caller. Owning ticket:
   US-0010 TK-0002.

## Decisions

- **Skill scale (finding 4):** world crew accuracy/maneuver validation widens from 0..30 to 0..100.
  The starter manifest carries the Board's values (55/52/55, 53/55/53, 59/54/59, 50/51/50); owned
  drones use the persistent crew record for identity (CrewId/name/gender/portrait/role) and for
  skills/initiative. Enemy/scenario drones keep `pilots.json` aliases. Legacy owned wings whose
  crew skills are both 0 fall back to the encounter alias's catalog values, preserving old saves.
- **Disabled/damage persistence:** add optional `disabled` and `engineFactors` to
  `OwnedDroneData` (schema 1 stays; absent fields mean intact/Air). Settlement writes them; assembly
  restores them; readiness exposes a `disabled` reason; a disabled drone is not combat-ready but is
  not destroyed and keeps its pilot/slot/magazine.
- **Hangar readiness:** ready-wing filter = `!Destroyed && !Disabled && IsHangarReady(HangarModuleId)`.
  If no ready drones remain, return `NoReadyDrones`.
- **Rearm UI:** ShipScreen selects a drone, quantity defaults to `min(gap, cargo stock)`, preview
  shows magazine/cargo transition, confirm sends exactly one request through the existing
  `GameSessionHandle.RearmDroneAsync`; pending blocks duplicates; no local optimistic spend.
- **Appearance:** pass the world `CarrierOperations.AppearanceId` into the tactical frame; the main
  renderer and minimap resolve it through `CarrierAppearance.ResourceKey`, falling back to the
  default carrier sheet only when the resource is missing. No new PNG; hitbox/rotation unchanged.
