## Подтверждённые проблемы

### F01 · P1 · EP-0001 / US-0013 / TK-0002, TK-0004, TK-0005 — cargo-upgrade не меняет проверяемый корабль

[BalanceRun.cs](../../../tools/DeepSpaceSaga.EconomyBalance/BalanceRun.cs), строки 397–402: обычный runner умножает только `analytical` capacity, затем ограничивает партию `buyQuote.MaximumQuantity`, рассчитанным для исходного трюма. При multiplier=2000 партия остаётся ограниченной исходной вместимостью. Обе конфигурации используют один registry. Поэтому `long_upgrade_crossover` не проверяет реальное удвоение трюма, и нужный переход из убытка в прибыль нельзя доказать этой конфигурацией. Cluster runner уже устанавливает увеличенную capacity в registry, но обычный 24-case runner этого не делает.

Исправление: согласовать историческое аналитическое допущение US-0013 с критерием crossover и использовать реальную конфигурацию registry в обеих ветках, сохранив authoritative quotes/receipts. Затем повторить 24-case release gate; не ослаблять evaluator ради зелёного отчёта.

### F02 · P2 · EP-0003 / US-0006 / TK-0001 — загрузчик принимает наложенные станции

[StationClusterSaveValidation.cs](../../../src/DeepSpaceSaga.Engine/Scenario/StationClusterSaveValidation.cs), строки 56–65: проверяются круговая орбита, период, пояс и связность, но отсутствует проверка пространственного разделения станций. Реальный JSON round-trip с seed=42, в котором `CLUSTER-4-STATION-10` получает орбиту/координаты `CLUSTER-4-STATION-1`, успешно загружается. Snapshot подтверждает расстояние **0**. Обновлены обе materialized записи орбиты, поэтому это не рассогласованный DTO, а принятая невалидная геометрия. Такая сеть нарушает размещение кластера и создаёт нулевую дистанцию для маршрута/топливного расчёта.

Исправление: проверять геометрические инварианты materialized cluster до публикации, с явным сохранением legacy-исключения близких исходных станций. Добавить негативный реальный JSON load и проверку неизменности прежнего мира. [Воспроизводимый probe](Probes/Program.cs).

### F03 · P2 · EP-0002 / US-0001 и EP-0003 / US-0004, US-0005 — Vmax зависит от имени типа двигателя

[SimulationEngine.cs](../../../src/DeepSpaceSaga.Engine/SimulationEngine.cs), строки 3226–3235, разрешает `MaxSpeedKmS` только для `module.engine.basic`. Генератор системы, напротив, принимает operational engine с любым TypeId и положительным MaxSpeedMps. Probe переименовывает тип в `module.engine.review`, задаёт 1400 m/s: New Game успешно создаётся, но snapshot публикует **MaxSpeedKmS=null**. Client не может показать оценку пути; [ClusterVoyages](../../../src/DeepSpaceSaga.Engine/SimulationEngine.ClusterVoyages.cs), строка 29, подставляет legacy reference speed вместо 1.4 km/s. Это нарушает data-driven контракт и правило ETA по установленному Vmax.

Исправление: один согласованный resolver рабочего двигателя для генератора, snapshot и cluster adapter; тест пользовательского TypeId, выключенного/повреждённого двигателя и нескольких двигателей.

### F04 · P2 · EP-0002 / US-0001 / TK-0002–0003 — нет практической верхней границы работы генератора

[SolarSystemGeneration.cs](../../../src/DeepSpaceSaga.Engine/Scenario/SolarSystemGeneration.cs), строки 46–56, принимает `AsteroidsPerBelt=int.MaxValue` и `MaxPlacementAttempts=int.MaxValue`. Probe подтвердил принятие обоих значений без запуска опасно большого цикла. [SolarSystemGenerator.cs](../../../src/DeepSpaceSaga.Engine/Scenario/SolarSystemGenerator.cs), строки 29, 69, 134–137, использует эти значения как реальные пределы циклов, включая вложенные попытки. Ошибка content может надолго заблокировать New Game или исчерпать память вместо ранней диагностики. Это риск custom/malformed content, не наблюдённый отказ штатного preset.

Исправление: документированные верхние бюджеты объектов/попыток и проверка их произведения до генерации; отрицательные и max+1 cases. Ограничение декоративного рендера 65536 samples не ограничивает количество настоящих астероидов Engine.

### F05 · P2 · EP-0001 / US-0001 / TK-0004 — ошибка отмены в интеграционном тесте маскирует исходный timeout

[StationMarketDemoContentTests.cs](../../../tests/DeepSpaceSaga.Client.Tests/StationMarketDemoContentTests.cs), строка 419: `MoveNextAsync().AsTask().WaitAsync(cancellationToken)` может завершить ожидание по отмене до завершения самого MoveNext. Выход из `await using` тогда вызывает DisposeAsync на ещё выполняющемся async iterator. Общий прогон получил `NotSupportedException` из DisposeAsync в промышленном case; повторный изолированный прогон всех пяти cases прошёл. Это подтверждённый сбой/нестабильность теста; причина задержки игрового пути не установлена.

Исправление: отменять сам snapshot stream, дождаться завершения активного MoveNext перед dispose, сохранять диагностический timeout с последним snapshot. Не объявлять это доказанным дефектом сделки.
