# Отладочная панель боя

Панель доступна на тактическом экране во всех сборках. `debugPanel` из
`Data/UI/combat-input.json` по умолчанию равен F12. Повторное нажатие закрывает
панель; Esc сначала отменяет прицел, затем закрывает панель. Открытие не ставит
игру на паузу. Панель справа имеет логическую ширину360px, масштабируется вместе
с UI и прокручивается до нижнего края. Она перехватывает мышь раньше прицела,
угроз и зума. Клавиатурное маневрирование и бой продолжаются; навигационные
клавиши сфокусированного accordion докладов принадлежат этому accordion.

## Параметры и авторитет

В пяти сворачиваемых секциях находятся25 перечисленных параметров: два двигателя
по три поля; два торпедных аппарата по reload и трём парам speed/radius; ПРО с
reload и двумя парами speed/radius. Число29 в исходной спецификации было ошибкой
подсчёта. Дефолты берутся из исходного каталога, а не из UI или текущего overlay.

| Типы/поле | Диапазон | Шаг / Ctrl-шаг |
|---|---|---|
| tetrarch/strizh: `maxSpeedKmS` |0,1–50 км/с|0,5 /0,1|
| tetrarch/strizh: `accelerationMps2` |10–20000 м/с², целое|50 /10|
| tetrarch/strizh: `turnRateDegPerSec` |1–360 °/с, целое|2 /1|
| Все аппараты: `reloadMs` |100–600000 мс, целое|500 /100|
| Профили аппаратов: `speedKmS` |0,1–100 км/с|0,5 /0,1|
| Торпедные профили: `blastRadiusKm` |0,05–50 км|0,5 /0,1|
| Профили ПРО: `blastRadiusKm` |0,05–50 км|0,25 /0,05|

ID двигателей: `module.engine.tetrarch`, `module.engine.strizh`. Торпедные
аппараты: `module.torpedo.launcher.basic`, `module.torpedo.launcher.light`,
профили `slow/medium/fast`.
ПРО: `module.countermeasure.launcher.basic`, профили `wide/fast`. Имена ключей
чувствительны к регистру. Maximum speed нормализуется в целые м/с с округлением
половины от нуля; snapshot возвращает фактически принятое значение.

Каждый +/- или колесо над числом отправляет одно поле `debug.tuning.apply`.
`DebugTuningPatch` может содержать несколько полей; Engine валидирует весь patch
до изменения состояния. Неизвестный ключ, неверный диапазон/целочисленность и
неработающая сессия имеют разные reason codes. На паузе, в доке и диалоге tuning
принимается. CommandId дедуплицируется; RNG, ownership и идентичность объектов
сохраняются. Snapshot несёт Revision, Values и исходные Defaults; compact frame
опускает неизменившийся overlay, а Client сохраняет предыдущий подтверждённый.

Неподтверждённое значение показано курсивом, быстрые клики накапливают ожидаемую
цель. Отказ возвращает действующее значение и локализованную красную причину.
Изменённое подтверждённое значение выделено оранжевым акцентом существующей
палитры, рядом серым показан дефолт. Граничная кнопка отключена. Кэшированные
Skia fonts/paints/text blobs пересоздаются только при изменениях и освобождаются
при завершении сессии или Defeat, включая переход из-под модального экрана.

## Момент применения

Engine применяет tuning в фазе команд игрока. Корабль сохраняет позицию и курс,
скорость ограничивается новым максимумом; engine/Approach/evasion/NPC steering
и независимые удержания получают новые лимиты. Движение станции в доке остаётся
принадлежностью станции. Новые AI решения из UI не вычисляются.

Снаряд сохраняет уже выбранный endpoint, damage и scatter. При смене скорости
текущая P(t) становится новым anchor; deadline равен t + расстояние/новая скорость.
Радиус действует на ещё не взорвавшийся снаряд. При совпавшем deadline сначала
разрешаются ПРО, затем торпеды, с устойчивым порядком ID. Неизменившийся профиль
не перезаписывает captured flight из сохранения после правки каталога.

У перезаряжающегося аппарата новый readyAt = старый readyAt − старый reload +
новый reload, но не раньше текущего физического времени. Готовый аппарат не
меняется. Достигнутая готовность даёт один соответствующий reload-complete факт.

## Файлы и продолжение

Каталог `DebugTuning` находится рядом с executable. После подтверждённых изменений
Client пишет полный UTF-8 `debug-tuning.json`: schemaVersion1, writtenAtUtc,
`ships`, `launchers` и вложенные `profiles`. Фоновая очередь объединяет revisions,
записи разделены минимум250мс; временный файл атомарно заменяет текущий.
Ошибка записи отображается; конечное состояние flush выполняется до закрытия
приложения и до чтения файла заменяющей сессией.

При каждом старте приложения `debug-tuning.defaults.json` перезаписывается из
исходного каталога, с `source: catalog`. Текущий файл не участвует в вычислении
этого reference. «↺» отправляет дефолт строки. «Сбросить всё» требует второго
клика не позднее1с, отправляет все дефолты одной командой и удаляет только текущий
файл после matching Executed receipt и подтверждённых Defaults. Последующий edit
побеждает удаление. «Открыть папку» открывает этот каталог в системном проводнике.

New Game, выбранный сценарий и Load читают текущий файл только при bootstrap,
без watcher. Частичный файл допустим: отсутствующие поля берутся из каталога.
Неверный JSON, ключ, версия, тип или диапазон отвергают весь файл; путь и причина
попадают в журнал и StartupError первой открытой панели. Отсутствующий файл не
является ошибкой. После Load сначала восстанавливается saved overlay, затем
валидный startup patch применяется обычной командой; он может retime restored flight.

Writer Save19 сохраняет только отличия tuning от каталога и provenance исходного
полёта. Save18 проходит явную миграцию; поля Save19 внутри Save18 отвергаются,
Save17 и старше не принимаются. Повреждённый файл не заменяет действующий мир.
Ввод клавиш в сейв не входит: сохраняется sampled pose, а удержания сбрасываются.

## Проверка вручную

Панели модулей читают обновлённые admitted snapshot-параметры после tuning:
скорости, дальности, scatter, reload и engine times не остаются локальной копией
старого каталога. Retiming выполняет Engine; Client только преобразует
длительность в real seconds. Правила — в [PointAimCombat](PointAimCombat.md#панели-модулей).

Открыть `PlayerShipOnly`, нажать F12, изменить max speed Тетрарха на5,5 и дождаться
статуса записанного файла. Проверить полный25-параметровый JSON, Ctrl-шаг, строковый
сброс и подтверждённый общий сброс с сохранностью reference. На другой сессии
проверить startup partial/reject, Load с летящим снарядом и retiming без скачка.
Повторить RU/EN и поддерживаемые масштабы. Справка объясняет предел орбитальной
скорости Мухи и упрощение упреждения при быстрых торпедах.
